Building robust multi-agent systems requires structured fault tolerance. LLM provider outages, network timeouts, invalid tool arguments, and unexpected exceptions must be handled gracefully without corrupting conversation state.

`chatflow-agent` implements a layered recovery model: tool errors are reported to the LLM as a generic error result so the turn can continue, while an ordinary exception that escapes the turn truncates the conversation history to its pre-turn length (v0.3.4 does not restore the active agent or metadata, and does not roll back cancelled turns).

## SDK Exception Hierarchy

All exceptions in `chatflow-agent` inherit from `ChatFlowError`. This allows your application to distinguish between framework-level errors and standard Python exceptions.

```text
ChatFlowError (Base)
├── DependencyError (Missing optional extra dependencies)
├── ToolExecutionError (Uncaught error during tool execution)
├── ToolSchemaError (Union annotation with an unmappable member) [v0.4.0rc1]
├── AgentHandoffError (Unknown handoff target)
├── ProviderError (LLM API status error, network failure, or timeout)
├── ReentrantTurnError (Nested same-session turn started from a running turn) [v0.4.0rc1]
└── SessionDeletedError (Message dispatched to a deleted session) [v0.4.0rc1]
```

### Exception Reference Table

| Exception Class | Inherits From | Raised When | Recovery Strategy |
| :--- | :--- | :--- | :--- |
| `ChatFlowError` | `Exception` | Base class for all SDK exceptions. | Catch at top-level request boundaries. |
| `DependencyError` | `ChatFlowError` | An optional channel extra (e.g. `[telegram]`, `[whatsapp]`) is not installed. | Install the required extra via `pip install "chatflow-agent[extra]"`. |
| `ToolExecutionError` | `ChatFlowError` | A tool function raises an uncaught exception during execution. | Inside a turn, `Runner` logs it and returns a generic `ToolResult(is_error=True)` to the model. |
| `ToolSchemaError` <VersionBadge version="0.4.0rc1" status="prerelease" /> | `ChatFlowError` | A tool is created with a union annotation that contains a member with no schema mapping. Unannotated parameters are allowed. | Fix function type signatures at development time. |
| `AgentHandoffError` | `ChatFlowError` | The handoff target does not exist in the `Runner` registry. Exceeding `max_handoffs_per_turn` does not raise: it adds an error tool result instead. | Verify handoff targets. |
| `ProviderError` | `ChatFlowError` | Upstream model provider returns an HTTP error code (e.g. 429, 500, 503). | Implement exponential backoff or failover to a fallback engine. |
| `ReentrantTurnError` <VersionBadge version="0.4.0rc1" status="prerelease" /> | `ChatFlowError`, `RuntimeError` | Code executing inside a turn starts another turn for the same session. | Use background job queues or follow-up turn dispatchers. |
| `SessionDeletedError` <VersionBadge version="0.4.0rc1" status="prerelease" /> | `ChatFlowError` | A message is processed for a session that was purged during execution. | Re-create session or notify the user to restart the workflow. |

## Autonomous Tool Self-Correction

When a registered tool raises an exception, including a `TypeError` from arguments the function does not accept, `Runner` catches the failure and returns a structured error to the model instead of crashing the turn. v0.3.4 does not validate tool arguments against the schema before calling the function:

```python
import logging
from chatflow_agent import Agent, Runner, tool

logger = logging.getLogger("app.tools")

@tool
def process_refund(order_id: str, amount: float) -> str:
    """Issue a refund for an order.

    Args:
        order_id: Order identifier formatted as ORD-XXXX.
        amount: Positive monetary value to refund.
    """
    if not order_id.startswith("ORD-"):
        raise ValueError("Invalid order format. Order ID must begin with 'ORD-'.")
    if amount <= 0:
        raise ValueError("Refund amount must be strictly greater than 0.")
    return f"Refund of ${amount:.2f} processed for order {order_id}."

agent = Agent(
    name="RefundBot",
    model="gpt-4o",
    provider="openai",
    tools=[process_refund],
    instructions="Process refunds accurately. If an order ID format is invalid, clarify with the user.",
)

runner = Runner(starting_agent=agent)
```

### What Happens During Execution

1. The model invokes `process_refund(order_id="12345", amount=50.0)`.
2. `process_refund` raises `ValueError: Invalid order format. Order ID must begin with 'ORD-'.`.
3. `Runner` assigns a unique `trace_id` (UUID4) and appends a `ToolResult`:
   ```json
   {
     "tool_call_id": "call_abc123",
     "name": "process_refund",
     "content": "Tool execution failed [trace_id: a8c2...]. Please try a different approach or inform the user.",
     "is_error": true
   }
   ```
4. The original exception is logged internally with the same `trace_id`. The model receives only the generic `is_error=True` result and cannot infer the private exception detail unless the application supplies it separately.

<Callout type="info" title="Loop Limit Protection">
To prevent infinite retry loops where an agent repeatedly fails a tool call, `Runner` enforces `max_tool_iterations` (default: `10`). If the limit is reached without a final text response, the runner returns a controlled fallback message without hanging.
</Callout>

## Transactional Turn Rollback

Multi-agent turns may modify conversation history, switch the active agent, and update metadata. Stable v0.3.4 provides a narrower rollback guarantee than a full transaction.

For ordinary exceptions caught by `Runner`, v0.3.4 truncates only `session.history` to its pre-turn length:

```text
Turn Start
    ├── Capture Checkpoint: history length
    ├── Append Inbound User Message
    ├── Execute LLM Turns & Tools
    │     ├── Success: Commit final assistant response to SessionStore
    │     └── Ordinary exception: truncate history to its previous length
    └── Release Session Lock
```

### Rollback Example in Code

```python
import asyncio
from chatflow_agent import Agent, Runner
from chatflow_agent.exceptions import ProviderError

def build_resilient_runner(agent: Agent) -> Runner:
    """Configure a runner with bounded handoffs and tool iterations."""
    return Runner(
        starting_agent=agent,
        max_tool_iterations=6,
        max_handoffs_per_turn=3,
    )

async def execute_turn_with_recovery(
    runner: Runner,
    session_id: str,
    user_message: str,
) -> str:
    """Execute a turn with explicit exception handling and graceful fallback."""
    try:
        response = await runner.run_async(
            session_id=session_id,
            user_message=user_message,
        )
        return response.content
    except ProviderError as err:
        # v0.3.4 rolls back history for this ordinary exception.
        # active_agent and metadata are not restored.
        return "Our AI inference service is temporarily degraded. Please retry in a few moments."
    except TimeoutError:
        # External cancellation in v0.3.4 does not guarantee rollback.
        return "The request took too long to complete. Please try a simpler question."
    except Exception as err:
        return "An unexpected system error occurred. Our operations team has been notified."
```

## Turn Timeouts & Resource Boundaries

Stable v0.3.4 has no `turn_timeout` parameter. Wrapping `run_async` in `asyncio.wait_for` cancels the task, but `CancelledError` is not caught by the runner's `except Exception` block, so history rollback is not guaranteed. Prefer provider and channel request timeouts; if an application uses external cancellation, it must treat the affected session as potentially partial and recover it explicitly.

```python
# [no-exec: illustrative turn timeout call]
import asyncio
from chatflow_agent import Runner

async def run_with_external_timeout(runner: Runner):
    try:
        return await asyncio.wait_for(
            runner.run_async(
                session_id="customer-1029",
                user_message="Analyze this quarterly financial audit report...",
            ),
            timeout=45.0,
        )
    except asyncio.TimeoutError:
        # v0.3.4: recover or discard this session explicitly before reusing it.
        raise
```

<Callout type="info" title="Transactional timeout in prerelease">
<VersionBadge version="0.4.0rc1" status="prerelease" /> introduces the explicit `turn_timeout` parameter and restores history, active agent, and metadata when that timeout expires. This guarantee does not apply to stable v0.3.4.
</Callout>

## Best Practices Checklist

- **Catch `ChatFlowError`:** Intercept framework exceptions before letting them propagate to HTTP handlers.
- **Set Bounded Iterations:** Never set `max_tool_iterations` or `max_handoffs_per_turn` to unbounded values.
- **Return Meaningful Tool Errors:** The model never sees the text of an exception raised by a tool, only a generic error with a `trace_id`. If the model should react to a specific problem (for example a malformed order ID), have the tool **return** a short, user-safe error message instead of raising.
- **Log Correlation IDs:** Capture the `trace_id` generated in `Runner` logs to correlate customer error reports with internal trace logs.
