`chatflow-agent` is built around five composable abstractions. Understanding how they interact makes it straightforward to design everything from a single tool-using chatbot to a multi-provider agent swarm.

## 1. `Agent` — Persona, Tools, and Routing Rules

An `Agent` (`chatflow_agent.core.agent.Agent`) is a declarative configuration object representing an AI specialist. An agent does **not** hold conversation state itself; instead, it defines:

* **`name`** (`str`): Unique identifier within a swarm (e.g., `"TriageAgent"`, `"BillingSpecialist"`). Used to synthesize handoff tool names (`transfer_to_billingspecialist`).
* **`instructions`** (`str | Callable[[], str]`): The system prompt—either a static string or a zero-argument callable evaluated dynamically at the start of every turn.
* **`model`** (`str`): Model identifier (default `"gemini-2.5-flash"`).
* **`tools`** (`list[Tool | Callable]`): Functions the agent is authorized to execute, validated at runtime by Pydantic (`validate_args=True` by default).
* **`handoffs`** (`list[Agent]`): Target agents to which this agent can delegate the conversation.
* **`provider` / `base_url` / `api_key` / `engine`**: Optional routing overrides allowing each agent in a swarm to run on a different LLM provider. Invalid provider names or missing credentials on custom remote endpoints fail fast with `ConfigurationError`.

```python
# [executable]
from datetime import datetime, timezone
from chatflow_agent import Agent

def dynamic_prompt() -> str:
    now = datetime.now(timezone.utc).strftime("%Y-%m-%d %H:%M UTC")
    return f"You are a support specialist. Current server time: {now}."

agent = Agent(
    name="SupportSpecialist",
    instructions=dynamic_prompt,
    model="gpt-4o",
)

assert "Current server time:" in agent.get_instructions()
```

## 2. `Runner` — The Turn Orchestrator

The `Runner` (`chatflow_agent.core.runner.Runner`) coordinates execution across sessions, agents, engines, and tools:

1. **Agent Registry Discovery:** At initialization, `Runner` performs a breadth-first traversal starting from `starting_agent` across all `.handoffs` edges, registering every reachable `Agent`. If two distinct `Agent` instances share the same `.name`, `Runner` raises `ValueError` immediately.
2. **Per-Session Concurrency Lock:** Calls to `run_async()` for the same `session_id` acquire a dedicated `asyncio.Lock`, preventing concurrent turns from corrupting conversation history. In `v0.4.0`, if a tool or background task spawned inside a turn attempts to call `run()` or `run_async()` on the **same** `session_id`, `Runner` immediately raises `ReentrantTurnError` instead of deadlocking.
3. **Session-Safe Reset (`reset_session_async`):** `await runner.reset_session_async(session_id)` and `runner.reset_session(session_id)` coordinate history clearing with the session turn lock, sync-work barrier, and reentrancy guard.
4. **Bounded Execution Loop:** Within a single turn, `Runner` enforces `max_tool_iterations` (default `10`) and `max_handoffs_per_turn` (default `5`) so runaway tool loops or circular handoffs never hang your service.
5. **Transactional Turn Rollback:** If an engine raises `ProviderError`, a handoff fails, or a turn is cancelled or exceeds `turn_timeout`, `Runner` restores the session's message history, `active_agent`, and `metadata` to the exact pre-turn state.

## 3. `BaseEngine` — Pluggable LLM Inference

Engines (`chatflow_agent.core.engines.base.BaseEngine`) implement a single asynchronous contract:

```python
async def generate_turn_async(
    self,
    agent: Agent,
    history: list[Message],
) -> EngineTurnResult:
    ...
```

Out of the box, `chatflow-agent` ships three production engines—all powered by `httpx.AsyncClient` with zero heavy provider SDK dependencies:

* **`GeminiEngine`**: Communicates directly with the Google Gemini REST API (`https://generativelanguage.googleapis.com/v1beta`), with automatic exponential backoff, `Retry-After` support, collision-resistant synthetic tool-call IDs (`cf_gemini_<24 hex>`), and API key redaction.
* **`OpenAIEngine`**: Supports OpenAI (`https://api.openai.com/v1`) plus built-in presets for `deepseek`, `groq`, `grok`, and local `ollama`, with stateless collision-resistant synthetic tool-call IDs (`call_<24 hex>`).
* **`AnthropicEngine`**: Connects to the Anthropic Messages API (`/v1/messages`) with native `tool_use` / `tool_result` block translation and configurable `max_tokens: int = 4096`.

## 4. `Tool` & `@tool` — Validated Function Calling

A `Tool` (`chatflow_agent.core.tools.Tool`) wraps a sync or async Python function:

* Inspects Python type hints (`str`, `int`, `float`, `bool`, `list[T]`, `dict[K, V]`, `Literal[...]`, `Enum`, `Optional[T]`, nested Pydantic `BaseModel`) via `pydantic.TypeAdapter` to compile a strict JSON Schema. Raises `ToolSchemaError` at definition time if a parameter type cannot be converted.
* Validates and coerces model-supplied arguments at runtime before calling the function (`validate_args=True` by default), raising `ToolArgumentValidationError` (a `ToolExecutionError` subclass) on invalid arguments.
* Dispatches sync functions directly and awaits coroutine functions (`inspect.iscoroutinefunction`).
* If a tool raises an exception at runtime, `Runner` catches it, logs a correlation `trace_id` with stack trace, and returns a sanitized `ToolResult` (`is_error=True`) to the LLM so the agent can recover gracefully without leaking internal stack traces to end users.

## 5. `BaseSessionStore` & `SessionContext` — State & Memory

Conversation state is encapsulated in `SessionContext`:

* **`session_id`** (`str`): Unique conversation key (e.g., a WhatsApp phone number, Telegram chat ID, or UUID).
* **`history`** (`list[Message]`): Ordered sequence of `USER`, `ASSISTANT`, `TOOL`, and `SYSTEM` messages, bounded by a sliding window (`max_turns`, default `50` user turns) that preserves tool-call pairs and keeps a `[System Note]` anchor at the head of trimmed conversations.
* **`active_agent`** (`Agent`): The agent currently handling the session. When a handoff occurs, `active_agent` updates and persists across future turns.
* **`metadata`** (`dict[str, Any]`): Arbitrary JSON-serializable key-value dictionary persisted alongside the session (with deep-copy isolation in `SessionStore`, ISO-8601 serialization for `datetime`/`date`/`time` values, and `JsonCodecError` for non-serializable objects).

Choose between:
* **`SessionStore`**: Fast in-memory dictionary store with deep-copied metadata isolation and thread-safe message deduplication.
* **`SQLiteSessionStore`**: Durable SQLite database store with `WAL` journaling, persistent `:memory:` support, single-transaction reads, transactional turn rollback journals, and 192-hour (`8-day`) webhook message deduplication.
