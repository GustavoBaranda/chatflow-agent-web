`chatflow-agent` is distributed on [PyPI](https://pypi.org/project/chatflow-agent/) with a minimal core footprint. In **`v0.4.0`**, the core package depends only on **`pydantic>=2.6.0`** and **`httpx>=0.27.0,<1.0`** (`google-genai` was removed in `v0.4.0` because `GeminiEngine` now communicates directly with the Gemini REST API over `httpx.AsyncClient`). Channel integrations (`telegram`, `whatsapp`, `webhook`) are packaged as optional extras so production containers stay lean.

## System Requirements

* **Python:** `>= 3.10` (`Requires-Python: >=3.10`; tested across Python 3.10, 3.11, 3.12, and 3.13)
* **Package Managers:** `pip`, `uv`, or `poetry`
* **Operating Systems:** The SDK CI runs on Linux (Ubuntu) and Windows. Because `chatflow-agent` is pure Python with no platform-specific markers, it is expected to work on macOS and arm64 as well, though they are not part of the CI matrix.
* **Core Dependencies (Installed Automatically):**
  * `pydantic >= 2.6.0` (Data validation, runtime tool argument validation, and schema helpers)
  * `httpx >= 0.27.0, < 1.0` (Async HTTP transport for OpenAI, Gemini, Anthropic, Ollama, and WhatsApp)
  * SQLite persistence uses Python's built-in `sqlite3` library with no third-party database drivers.

## Installing the Package

<Steps>
  <Step>
    ### Create an Isolated Virtual Environment

    Always install `chatflow-agent` inside a dedicated virtual environment:

    <Tabs items={['venv (Standard)', 'uv', 'poetry']}>
      <Tab value="venv (Standard)">
```bash
python -m venv .venv

# Linux / macOS
source .venv/bin/activate

# Windows (PowerShell)
.venv\Scripts\Activate.ps1
```
      </Tab>
      <Tab value="uv">
```bash
uv venv
source .venv/bin/activate
```
      </Tab>
      <Tab value="poetry">
```bash
poetry add chatflow-agent@0.4.0
```
      </Tab>
    </Tabs>
  </Step>

  <Step>
    ### Install `chatflow-agent` v0.4.0

    Choose the installation command matching your deployment needs:

    <Tabs items={['Core SDK (0.4.0)', 'Telegram Extra', 'WhatsApp Extra', 'Webhook Extra', 'All Extras']}>
      <Tab value="Core SDK (0.4.0)">
```bash
pip install chatflow-agent==0.4.0
```
      </Tab>
      <Tab value="Telegram Extra">
```bash

```
      </Tab>
      <Tab value="WhatsApp Extra">
```bash

```
      </Tab>
      <Tab value="Webhook Extra">

      </Tab>

## Core Dependencies & Optional Extras Matrix

The table below reflects the exact `METADATA` (`Requires-Dist` and `Provides-Extra`) published in the **`chatflow-agent==0.4.0`** wheel:

| Track / Extra | Install Command | Packages Added | Required By |
| :--- | :--- | :--- | :--- |
| *(Core — always installed)* | `pip install chatflow-agent==0.4.0` | `pydantic>=2.6.0`, `httpx>=0.27.0,<1.0` | `Agent`, `Runner`, `OpenAIEngine`, `GeminiEngine`, `AnthropicEngine`, `SessionStore`, `SQLiteSessionStore`, `CLIChannel` |
| `telegram` | `pip install "chatflow-agent[telegram]==0.4.0"` | `python-telegram-bot>=21.0` | `TelegramChannel` |
| `whatsapp` | `pip install "chatflow-agent[whatsapp]==0.4.0"` | `fastapi>=0.110.0`, `uvicorn>=0.29.0` | `WhatsAppChannel` |
| `webhook` | `pip install "chatflow-agent[webhook]==0.4.0"` | `fastapi>=0.110.0`, `uvicorn>=0.29.0` | Custom FastAPI HTTP endpoints (there is no built-in generic webhook channel; see [Custom Webhooks](/en/docs/v0.4/integrations/webhook)) |
| `all` | `pip install "chatflow-agent[all]==0.4.0"` | `python-telegram-bot>=21.0`, `fastapi>=0.110.0`, `uvicorn>=0.29.0` | Full multi-channel deployments |
| `dev` | `pip install "chatflow-agent[dev]==0.4.0"` | `pytest>=8.0.0`, `pytest-asyncio>=0.23.0`, `ruff>=0.4.0`, `mypy>=1.9.0` | Contributing and running the SDK test suite |

<Callout type="info" title="Lazy Channel Imports & DependencyError">
If you attempt to instantiate `TelegramChannel` or `WhatsAppChannel` without installing its corresponding extra, `chatflow-agent` raises a descriptive `DependencyError` with the exact `pip install` command needed.
</Callout>

## Configuring Provider API Keys

`chatflow-agent` automatically resolves provider credentials from standard environment variables when `api_key` is not passed explicitly to an `Agent` or engine constructor. Each provider reads only its own variable—and only when sending requests to that provider's official endpoint (`OPENAI_API_KEY` is never sent to another provider or custom remote host):

| Provider | Environment Variable | Default Model Preset | Engine Class |
| :--- | :--- | :--- | :--- |
| **Google Gemini** | `GEMINI_API_KEY` *(falls back to `GOOGLE_API_KEY` if unset; optional `GOOGLE_GEMINI_BASE_URL` for proxies)* | `gemini-2.5-flash` | `GeminiEngine` |
| **OpenAI** | `OPENAI_API_KEY` | `gpt-4o-mini` | `OpenAIEngine` |
| **Anthropic** | `ANTHROPIC_API_KEY` | `claude-3-5-sonnet-latest` | `AnthropicEngine` |
| **DeepSeek** | `DEEPSEEK_API_KEY` | `deepseek-chat` | `OpenAIEngine(provider="deepseek")` |
| **Groq** | `GROQ_API_KEY` | `llama-3.3-70b-versatile` | `OpenAIEngine(provider="groq")` |
| **xAI Grok** (`provider="grok"` or `"xai"`) | `XAI_API_KEY` | `grok-2` | `OpenAIEngine(provider="grok")` |
| **Ollama / Gemma (Local)** (`provider="ollama"` or `"gemma"`) | `OLLAMA_API_KEY` *(optional; local Ollama servers require no key)* | `gemma2:9b` | `OpenAIEngine(provider="ollama")` |

Export the variables in your shell before starting your application:

<Tabs items={['Linux / macOS (bash/zsh)', 'Windows (PowerShell)']}>
  <Tab value="Linux / macOS (bash/zsh)">
```bash
export OPENAI_API_KEY="sk-..."
export GEMINI_API_KEY="AIza..."
export ANTHROPIC_API_KEY="sk-ant-..."
export XAI_API_KEY="xai-..."
export DEEPSEEK_API_KEY="sk-..."
export GROQ_API_KEY="gsk_..."
```
  </Tab>
  <Tab value="Windows (PowerShell)">
```powershell
$env:OPENAI_API_KEY="sk-..."
$env:GEMINI_API_KEY="AIza..."
$env:ANTHROPIC_API_KEY="sk-ant-..."
$env:XAI_API_KEY="xai-..."
```
  </Tab>
</Tabs>
