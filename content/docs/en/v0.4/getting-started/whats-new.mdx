**`chatflow-agent` `0.4.0`** is the latest stable production release of the framework. It consolidates every architectural enhancement, runtime validation capability, security hardening improvement, and bug fix developed across the `0.4.0` release cycle into a unified stable baseline.

## Release Highlights (`0.3.4` → `0.4.0`)

| Area | `v0.3.4` (Previous Stable) | `v0.4.0` (Latest Stable) |
| :--- | :--- | :--- |
| **Tool Argument Validation** | Schema-only; raw LLM arguments passed directly to functions | **Runtime Pydantic validation enabled by default (`validate_args=True`)**, raising `ToolArgumentValidationError` |
| **Tool Schema Validation** | Invalid annotations fell back to `{}` or failed late | **Fail-fast `ToolSchemaError`** at tool creation + `Tool.to_openai_parameters()` public helper |
| **Gemini Transport** | Depended on `google-genai` SDK | **Direct Gemini REST API via `httpx.AsyncClient`** (`google-genai` dependency removed) |
| **Turn Rollback & Timeouts** | Rolled back messages and `active_agent` on standard `Exception` only | **Full transactional rollback of history, `active_agent`, and `metadata`** on `Exception`, `CancelledError`, and `turn_timeout` |
| **Session Concurrency** | Per-session `asyncio.Lock` (reentrant calls deadlocked) | **Reentrancy detection (`ReentrantTurnError`)**, `Runner.spawn_turn()`, and **`Runner.reset_session_async()`** |
| **Runner Lifecycle** | Manual engine cleanup | **`async with runner:`** async context manager (`__aenter__` / `__aexit__`) |
| **SQLite `:memory:`** | Opened a new empty in-memory DB per connection | **Persistent shared connection** for `SQLiteSessionStore(db_path=":memory:")` + single-transaction reads |

## 1. Runtime Tool Argument Validation (`validate_args=True`)

In `v0.3.4`, Python type hints on `@tool` functions only generated the JSON Schema sent to the LLM; model-supplied arguments were passed directly to your function without runtime checking.

In `v0.4.0`, **runtime argument validation is enabled by default (`validate_args=True`)**:

* Every tool call validates and coerces model-supplied arguments against the function's type annotations using a cached Pydantic `TypeAdapter` before invoking the function.
* **Practical LLM Coercion:** Unquoted integers and finite floats coerce cleanly to `str` targets (while booleans, lists, dicts, and `None` are rejected for `str`); string booleans (`"true"`, `"false"`) coerce to `bool`; numeric `int` and `float` parameters reject booleans (`True`/`False`) and non-finite values (`NaN`, `inf`, `-inf`).
* **Order-Independent Union Validation:** In unions containing `str` (such as `str | int` or `Optional[str | int]`), non-coercing branches are tried before string coercion so integer inputs like `5` remain `int`.
* **Reserved Parameter Support:** Parameters with leading underscores (`_id`), `model_config`, or plain functions taking `self` or `cls` are validated without colliding with Pydantic internals.
* **Sanitized Error Reporting:** Invalid arguments raise **`ToolArgumentValidationError`** (a subclass of `ToolExecutionError`) with bounded summaries (at most 3 field errors, capped at 300 characters) and suppressed internal Pydantic `__cause__` / `__context__` chains.
* **Per-Tool Opt-Out & Cloning:** Pass `validate_args=False` on `@tool`, `@agent.tool`, `agent.add_tool`, or `Tool(...)` to disable runtime validation for a specific tool. When a shared `Tool` instance is registered on multiple agents with a different `validate_args` override, `agent.add_tool()` clones the tool (`Tool.clone()`) so other agents are never mutated.

```python
# [min-version: 0.4.0]
# [executable]
from chatflow_agent import ToolArgumentValidationError, tool

@tool
def create_order(sku: str, quantity: int) -> str:
    """Create a warehouse order."""
    return f"Ordered {quantity}x {sku}"

assert create_order.execute(sku=1042, quantity="3") == "Ordered 3x 1042"

try:
    create_order.execute(sku="A-100", quantity="not-a-number")
except ToolArgumentValidationError as exc:
    assert "quantity" in str(exc)
```

## 2. Fail-Fast Tool Schema Validation & `Tool.to_openai_parameters()`

* **`ToolSchemaError` at Registration Time:** Forward references that cannot be resolved (`"UnknownType"`) or arbitrary custom classes that Pydantic cannot convert into JSON Schema now raise **`ToolSchemaError`** immediately when `@tool` or `Tool(...)` is evaluated.
* **`Tool.to_openai_parameters()` Public Helper:** Returns a deep copy of the normalized OpenAI-compatible JSON Schema parameters object (`{"type": "object", "properties": ..., "required": ...}`), hoisted `$defs`, and resolved nullable unions.
* **Static `@overload` Typing:** Both `@tool` and `@agent.tool` provide `@overload` signatures for bare (`@tool`) and parameterized (`@tool(...)`) usage so `mypy` and `pyright` infer the return type as `Tool`.

## 3. Runner Lifecycle, Full Turn Rollback & Concurrency Guards

### Asynchronous Context Manager & `turn_timeout`
* **`async with runner:`:** `Runner` implements the asynchronous context manager protocol (`__aenter__` / `__aexit__`), closing its pooled Gemini `httpx.AsyncClient` cleanly on exit.
* **`turn_timeout: float | None = None`:** Available on both `runner.run()` and `await runner.run_async()`. When a turn exceeds `turn_timeout` seconds, `Runner` aborts the turn, rolls back all session changes from that turn, and raises `TimeoutError`. (Passing a boolean `True`/`False` as `turn_timeout` raises `ValueError`.)

### Full Transactional Rollback (History, Active Agent, and Metadata)
* In `v0.3.4`, failed turns only rolled back newly appended messages and `active_agent` on standard `Exception` subclasses.
* In `v0.4.0`, failed, timed-out (`TimeoutError`), or cancelled (`asyncio.CancelledError`) turns roll back **message history, `active_agent`, and `session.metadata`** in both `SessionStore` (via deep-copied snapshots) and `SQLiteSessionStore` (via the `_turn_journal.prev_metadata` column).
* If the session is deleted while a turn is running, committing or rolling back raises **`SessionDeletedError`** instead of silently recreating a zombie session row.

### Reentrant Turn Detection & `Runner.spawn_turn()`
* Calling `runner.run()` or `await runner.run_async()` for the **same** `session_id` from inside an active turn (including from a tool, `asyncio.create_task`, `asyncio.gather`, `asyncio.TaskGroup`, or `asyncio.to_thread` worker) now raises **`ReentrantTurnError`** immediately instead of deadlocking on the per-session lock.
* To schedule an independent background turn for the same session from inside a tool, use **`runner.spawn_turn(session_id, user_message, ...)`**, which returns an `asyncio.Task` queued outside the current turn's reentrancy lineage.

### Session-Safe Reset (`reset_session_async` & `reset_session`)
* `await runner.reset_session_async(session_id)` and `runner.reset_session(session_id)` clear a session's history under the session turn lock, wait for any escaping synchronous thread work from a timed-out or cancelled turn, reject reentrant resets from inside an active turn with `ReentrantTurnError`, and offload synchronous SQLite writes via `asyncio.to_thread()`.

## 4. Direct Gemini REST Engine & Provider Enhancements

* **Direct `httpx` `GeminiEngine` (No `google-genai` Dependency):** `GeminiEngine` now talks directly to `https://generativelanguage.googleapis.com/v1beta` using a persistent `httpx.AsyncClient` (`follow_redirects=False`). It supports `timeout_seconds`, `max_retries`, `base_delay`, and `max_delay` constructor parameters, honors `Retry-After` headers (falling back to exponential backoff on negative or malformed values), and redacts the Gemini API key from all error messages and logs.
* **Agent `api_key` Honored on Default Gemini Fallback:** When an `Agent(api_key=...)` uses the default Gemini model without an explicit `engine`, `provider`, or `base_url`, `Runner.resolve_engine()` now clones the default `GeminiEngine` with the agent's `api_key`.
* **Configurable `AnthropicEngine(max_tokens=4096)`:** `AnthropicEngine` now accepts a keyword-only `max_tokens: int = 4096` parameter (validated with `ConfigurationError`) and logs a warning when a response is truncated with `stop_reason == "max_tokens"`.
* **Collision-Resistant Synthetic Tool-Call IDs:** When a provider response omits a tool call `id`, `OpenAIEngine` generates a stateless 29-character ID (`call_<24 hex>`) and `GeminiEngine` generates a 34-character ID (`cf_gemini_<24 hex>`, omitted when sending `functionResponse` parts back to Gemini while preserving real provider IDs byte-for-byte).
* **Strict Provider & Endpoint Validation (`ConfigurationError`):** Passing an unrecognized `provider` to `Agent` or `OpenAIEngine` without a `base_url`, combining `provider="gemini"`/`"google"` with a custom `base_url`, or passing a non-local `base_url` without an explicit `api_key` now raises **`ConfigurationError`** (a `ValueError` subclass).
* **Shared Credential Redaction & Sanitized `ProviderError`:** All engines (`OpenAIEngine`, `AnthropicEngine`, `GeminiEngine`) and `WhatsAppChannel` share a unified secret-redaction pipeline covering plain, JSON-escaped, and URL percent-encoded tokens, validate credentials for illegal HTTP header control characters before dispatch, and suppress raw `httpx` / `json.JSONDecodeError` exception chaining (`__cause__` and `__context__` are `None`) on `ProviderError`.

## 5. Session Stores, SQLite `:memory:` & `JsonCodecError`

* **Persistent `SQLiteSessionStore(db_path=":memory:")`:** Retains a single shared SQLite connection guarded by an internal `threading.RLock()` so tables and session rows survive across calls for the lifetime of the store instance.
* **Single-Transaction Reads & Faster Turn Startup:** `SQLiteSessionStore.get()` reads session metadata and messages inside one transaction, and `Runner.run_async()` starts the SQLite turn journal directly from the `SessionContext` returned by `get_or_create()` without a redundant second `refresh()` query.
* **Deep-Copied In-Memory Session Metadata:** `SessionContext` and `SessionStore` deep-copy `metadata` dictionaries on creation, turn updates, handoffs, and rollbacks so mutating an external dictionary never mutates live session state.
* **Thread-Safe `SessionStore` Deduplication:** `SessionStore.record_processed_message()` and `is_message_processed()` are now protected by an internal lock.
* **`JsonCodecError` & ISO-8601 Date/Time Metadata:** Session metadata containing `datetime`, `date`, or `time` instances serializes automatically to ISO-8601 strings; non-JSON-serializable objects (such as custom classes or functions) fail fast with **`JsonCodecError`** instead of silently coercing via `str()`.

## 6. Telegram & WhatsApp Channel Upgrades

### `TelegramChannel`
* **`concurrent_updates: bool | int | BaseUpdateProcessor = False`:** Keyword-only parameter enabling concurrent update processing across different chats while `Runner`'s per-session lock keeps turns within each chat serialized.
* **Bounded Flood-Control Retries (`max_retry_after_seconds: float = 60.0`):** When Telegram returns `telegram.error.RetryAfter` during multi-chunk outbound replies, `TelegramChannel` sleeps for `retry_after` seconds and retries only the unsent chunk (up to 3 times) without duplicating already-sent chunks or sending a contradictory `fallback_message` after partial delivery.
* **Session-Safe `/reset`:** Delegates to `await runner.reset_session_async(session_id)`.

### `WhatsAppChannel`
* **Removed Unused `dedup_ttl_hours` Parameter (Breaking Change):** Webhook deduplication TTL is configured exclusively on the session store (`SessionStore(dedup_ttl_hours=...)` or `SQLiteSessionStore(dedup_ttl_hours=...)`). `max_body_size`, `enable_docs`, and `queue_timeout_seconds` are now keyword-only parameters on `WhatsAppChannel`.
* **Outbound & Configuration Validation (`ConfigurationError`):** Validates `max_outbound_retries` (`0..10`), `outbound_base_delay >= 0`, `outbound_max_delay >= 0`, and `max_body_size > 0` at construction time, and logs a startup warning if `access_token` or `phone_number_id` is empty.
* **Strict `2xx` Outbound Delivery & Empty-Reply Guard:** Uses `follow_redirects=False`, treats only `2xx` responses as delivered (aborting remaining chunks immediately on the first failed chunk), and substitutes `fallback_message` if the agent returns an empty or whitespace-only string.
* **Webhook Privacy & Deterministic Fallback IDs:** Masks the `sender` phone number in webhook HTTP JSON responses (`_mask_phone()`), derives a deterministic SHA-256 fallback message ID (`gen_<sha256>`) when Meta omits `"id"`, and awaits any awaitable return value from `on_24h_window_expired`.

## 7. Complete Summary of New Public Exceptions in `0.4.0`

All 6 new exceptions are exported at the top level of `chatflow_agent` and `chatflow_agent.exceptions`:

| Exception | Base Class(es) | When Raised |
| :--- | :--- | :--- |
| `ConfigurationError` | `ChatFlowError`, `ValueError` | Invalid provider/engine configuration, unsupported `provider`, missing `api_key` on custom remote `base_url`, invalid `AnthropicEngine(max_tokens=...)`, or invalid `TelegramChannel` / `WhatsAppChannel` parameters. |
| `JsonCodecError` | `ChatFlowError` | Session `metadata` or tool payload contains an object that cannot be serialized to JSON. |
| `ToolSchemaError` | `ChatFlowError` | A `@tool` function or `Tool` definition uses an unresolved forward annotation or unsupported parameter type. |
| `ToolArgumentValidationError` | `ToolExecutionError` | Model-supplied or caller-supplied tool arguments fail runtime Pydantic validation (`validate_args=True`). |
| `ReentrantTurnError` | `ChatFlowError`, `RuntimeError` | `runner.run()`, `runner.run_async()`, or `runner.reset_session*()` is called for the same `session_id` from inside an active turn on that session. |
| `SessionDeletedError` | `ChatFlowError` | A running turn attempts to commit or roll back a session that was deleted concurrently. |
