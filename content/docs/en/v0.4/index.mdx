**`chatflow-agent`** is an open-source, lightweight, asynchronous Python framework engineered for orchestrating conversational AI agents, runtime-validated function calling, multi-agent handoffs, and multi-channel messaging pipelines without monolithic framework bloat.

<Callout type="info" title="chatflow-agent v0.4.0 — Latest Stable Release">
You are viewing the authoritative documentation for **`chatflow-agent` `v0.4.0` (`Latest / Stable`)**. Key `v0.4.0` capabilities include default runtime Pydantic tool-argument validation (`validate_args=True` and `ToolArgumentValidationError`), direct `httpx` Gemini REST transport (removing the `google-genai` dependency), full transactional turn rollback (history, active agent, and session metadata across exceptions, cancellations, and timeouts), reentrant-turn deadlock prevention (`ReentrantTurnError` and `Runner.spawn_turn()`), session-safe `Runner.reset_session_async()`, persistent in-memory SQLite (`db_path=":memory:"`), and strict `ConfigurationError` validation. Upgrading from `v0.3.4`? Read [What's New in 0.4.0](/en/docs/v0.4/getting-started/whats-new) and the [Migration Guide (0.3.4 → 0.4.0)](/en/docs/v0.4/getting-started/migration).
</Callout>

## System Architecture at a Glance

`chatflow-agent` cleanly decouples **conversational reasoning** (`Agent`), **execution orchestration** (`Runner`), **model inference** (`BaseEngine`), **state persistence** (`BaseSessionStore`), and **delivery channels** (`BaseChannel`):

```text
┌─────────────────────────────────────────────────────────────────────────┐
│                         Delivery Channels                               │
│     CLIChannel   │   TelegramChannel   │   WhatsAppChannel   │  FastAPI │
└─────────┬───────────────────┬─────────────────────┬───────────────┬─────┘
          │                   │                     │               │
          ▼                   ▼                     ▼               ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                       Runner (Turn Orchestrator)                        │
│  • Per-Session Async Locking       • Bounded Tool Loop (default: 10)    │
│  • Full Turn Rollback + Timeout    • Handoff Cycle Guards (default: 5)  │
└─────────┬─────────────────────────────────────────────────┬─────────────┘
          │                                                 │
          ▼                                                 ▼
┌───────────────────────────────────┐     ┌───────────────────────────────┐
│      Active Agent & Swarm         │     │     Session Persistence       │
│  • Instructions (str | Callable)  │     │  • SessionStore (In-Memory)   │
│  • @tool / Tool Registry          │     │  • SQLiteSessionStore (WAL)   │
│  • Handoff Targets (transfer_to_) │     │  • 192h Webhook Deduplication │
└─────────┬─────────────────────────┘     └───────────────────────────────┘
          │
          ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                        LLM Provider Engines                             │
│  • GeminiEngine (REST via httpx) • OpenAIEngine (OpenAI/Groq/DeepSeek)  │
│  • AnthropicEngine (Claude)      • Ollama (Local Offline Inference)     │
└─────────────────────────────────────────────────────────────────────────┘
```

## Core Design Principles

1. **Zero Hidden Magic:** Every agent transition, tool invocation, and database transaction is explicit and inspectable. Handoffs are synthesized as deterministic tool definitions (`transfer_to_<agent_name>`).
2. **Async-First Concurrency:** Built natively on Python `asyncio` and `httpx.AsyncClient`. `Runner` uses per-session `asyncio.Lock` instances to prevent race conditions when users send rapid consecutive messages, detects reentrant turns on the same session (`ReentrantTurnError`), and supports `async with runner:` for automatic engine cleanup.
3. **Runtime Tool Argument Validation:** Tools decorated with `@tool` or `@agent.tool` validate and coerce model-supplied arguments against Python type hints using Pydantic before executing the function (`validate_args=True` by default), raising `ToolArgumentValidationError` on invalid input.
4. **Transactional State Integrity:** `SQLiteSessionStore` runs in `WAL` (Write-Ahead Logging) mode with a turn rollback journal (`_turn_journal`). If an unhandled exception, cancellation, or `turn_timeout` aborts a turn mid-flight, history, `active_agent`, and `metadata` roll back to the pre-turn snapshot. Passing `db_path=":memory:"` keeps a single shared connection open so tables and session rows persist for the lifetime of the store instance.
5. **Multi-Provider Freedom:** Switch seamlessly between OpenAI (`gpt-4o`), Google Gemini (`gemini-2.5-flash`), Anthropic Claude (`claude-3-5-sonnet-latest`), DeepSeek, Groq, xAI Grok, and local Ollama models—or mix different providers within the same multi-agent swarm.
