Welcome to the preview documentation for **chatflow-agent v0.4.x**, featuring major concurrency and architectural upgrades.

Created and led by **Gustavo Baranda** alongside an international open-source community, `chatflow-agent` is designed to eliminate framework bloat and vendor lock-in while providing enterprise-grade concurrency, resilient memory, and multi-channel connectivity.

---

## Architecture Highlights

<Cards>
  <Card title="Zero-SDK Lock-In">
    Connects to LLMs over pure, asynchronous HTTP REST using `httpx`. No monolithic vendor SDKs or heavy runtime dependencies required.
  </Card>
  <Card title="Native Multi-Agent Handoffs">
    Declare collaborative swarms. Agents delegate tasks dynamically using synthesized `transfer_to_*` tools with automatic cycle prevention.
  </Card>
  <Card title="Transactional Resilient Memory">
    Every turn takes an atomic snapshot. If an error or timeout occurs, state automatically rolls back. SQLite operations run in dedicated thread pools.
  </Card>
  <Card title="Multi-Channel Readiness">
    Deploy your agents seamlessly to terminal REPLs, Telegram bots, or WhatsApp Business Cloud API with HMAC SHA-256 signature verification.
  </Card>
</Cards>

## Getting Started Path

Follow our structured onboarding guide to go from installation to a running production agent in minutes:

1. **[Installation](/en/docs/v0.4/getting-started/installation):** Verify your Python environment (`>=3.10`), install core packages, and configure optional channel extras.
2. **[Quickstart](/en/docs/v0.4/getting-started/quickstart):** Build your first agent in under 5 minutes, invoke custom tools with `@tool`, and explore asynchronous execution.
3. **[Core Concepts](/en/docs/v0.4/getting-started/core-concepts):** Learn the foundational architecture: `Agent`, `Runner`, `Engines`, `Tools`, `Memory`, and `Handoffs`.
