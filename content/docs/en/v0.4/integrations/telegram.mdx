`TelegramChannel` connects `chatflow-agent` swarms to Telegram bots. Powered by the asynchronous `python-telegram-bot` library, it handles polling, session isolation per chat ID, automatic message chunking, and security policies for group chats.

## Installation

Install `chatflow-agent` with the `telegram` extra to include required dependencies (`python-telegram-bot>=21.0`):

```bash
pip install "chatflow-agent[telegram]"
```

## Quickstart Bot Setup

<Steps>
  <Step>
    ### Create a Bot via BotFather

    1. Open Telegram and search for [@BotFather](https://t.me/BotFather).
    2. Send `/newbot` and follow the prompts to choose a display name and username.
    3. Copy the generated HTTP API Bot Token.
  </Step>

  <Step>
    ### Implement the Channel Script

    Create a script attaching a `Runner` to `TelegramChannel`:

```python
import os
from chatflow_agent import Agent, Runner
from chatflow_agent.channels import TelegramChannel
from chatflow_agent.core.memory import SQLiteSessionStore

# Define your agent
support_agent = Agent(
    name="SupportBot",
    instructions="You are a helpful customer support representative.",
)

# Configure persistent session storage
store = SQLiteSessionStore("telegram_sessions.db")
runner = Runner(starting_agent=support_agent, session_store=store)

# Initialize Telegram Channel
telegram = TelegramChannel(
    token=os.environ.get("TELEGRAM_BOT_TOKEN", "your-bot-token"),
    start_message="Welcome! How can I assist you today?",
)

# Attach runner and run polling loop
telegram.attach(runner)

if __name__ == "__main__":
    print("Starting Telegram bot polling...")
    telegram.run()
```
  </Step>
</Steps>

## Channel Configuration Parameters

The `TelegramChannel` constructor accepts the following options:

| Parameter | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `token` | `str` | *Required* | Telegram Bot API token issued by @BotFather. |
| `start_message` | `str` | `"Hello! I am your AI..."` | Greeting message sent when a user triggers `/start`. |
| `fallback_message` | `str` | `"Disculpa, ocurrió un..."` | User-facing message sent when model execution fails. |
| `allowed_updates` | `list[str] \| None` | `None` | Restrict update types (e.g. `["message"]`). Defaults to all. |

## Built-In Commands & Group Chat Security

`TelegramChannel` includes preconfigured command handlers:

### `/start` Command
Responds with `start_message` to onboard new users.

### `/reset` Command
Clears the session history in `runner.session_store` for the active chat ID, allowing users to restart their conversation cleanly.

<Callout type="warn" title="Group and Supergroup Chat Security">
In group and supergroup chats, allowing any participant to clear the conversation could disrupt other users. `TelegramChannel` enforces role verification:
* **Creators and Administrators:** Allowed to run `/reset`.
* **Standard Members:** Denied execution with the response: `"Only group admins can reset the conversation."`.

## Outbound Message Chunking (`split_message`)

Telegram enforces a strict maximum length of **4096 characters per text message**. When an agent generates long formatted analyses, code blocks, or tables, sending the full text directly causes the Telegram API to return HTTP 400.

`TelegramChannel` automatically pipes responses through `split_message`:

```python
# [min-version: 0.3.2]
# [executable]
from chatflow_agent.channels import split_message

long_text = "Detailed agent analysis..." * 200
chunks = split_message(long_text, max_len=4096)
# Splits progressively at \n\n, \n, . , or spaces to preserve readability
```

The channel delivers chunks sequentially. `split_message` prefers paragraph, line, sentence, and then word boundaries; when a chunk contains no separator (for example a very long URL), it falls back to a hard cut at `max_len`. Lengths are counted in Python characters, and `max_len` must be positive.

## Typing Indicators & User Experience

When a message arrives, `TelegramChannel` sends a single `ChatAction.TYPING` indicator before dispatching the turn (errors from that call are ignored). It is not repeated while the turn runs, so for long turns Telegram's typing status may disappear before the reply arrives.

## Event Loop Handling

`run()` starts long polling and blocks: it drives the event loop itself through python-telegram-bot's `run_polling()`. In v0.4.0rc1 it also opens the attached runner's `async with runner:` scope for the application's lifetime (entered in `post_init`, closed in `post_shutdown`), so turns reuse pooled Gemini connections. Passing `close_loop=False` keeps the event loop open after `run()` returns:

```python
telegram.run(drop_pending_updates=True, close_loop=False)
```

`close_loop=False` does not make `run()` usable inside an event loop that is already running, such as a FastAPI application's. `TelegramChannel` does not provide a non-blocking start method.
