Los sistemas de IA en producción requieren una separación nítida entre código y configuración. Siguiendo la metodología [Twelve-Factor App](https://12factor.net/config), las credenciales, direcciones de red y umbrales de ejecución deben transmitirse mediante variables de entorno en lugar de codificarse de forma fija en módulos de Python.

`chatflow-agent` implementa una jerarquía estructurada de resolución: los argumentos explícitos del constructor prevalecen sobre las variables de entorno, las cuales a su vez tienen prioridad sobre los valores por defecto del framework.

## Jerarquía de Resolución de Configuración

Al inicializar un agente o un motor, los valores se resuelven según el siguiente orden de precedencia:

```text
Prioridad 1: Argumentos Explícitos en el Constructor
    └── Agent(engine=OpenAIEngine(api_key="...", timeout=30.0))
          │ (Anula cualquier otra fuente)
          ▼
Prioridad 2: Variables de Entorno Específicas del Proveedor
    └── OPENAI_API_KEY, GROQ_API_KEY, GEMINI_API_KEY, ANTHROPIC_API_KEY
          │ (Cargadas desde os.environ)
          ▼
Prioridad 3: Preajustes y Valores por Defecto del Framework
    └── URLs base (https://api.openai.com/v1), modelos por defecto, timeout de petición
        (60.0s para OpenAIEngine y AnthropicEngine, 30.0s para GeminiEngine)
```

## Referencia de Variables de Entorno

El propio SDK solo lee las variables de proveedores que aparecen a continuación. Las variables de canales de la segunda tabla son una convención de nombres para el código de tu aplicación (pasa tú mismo los valores a los constructores de los canales); el SDK no las lee.

### Credenciales de Proveedores de LLM

| Variable | Proveedor Objetivo | Descripción | Valor de Respaldo |
| :--- | :--- | :--- | :--- |
| `OPENAI_API_KEY` | OpenAI | Token Bearer para endpoints oficiales de OpenAI. | `None` (Requerido para OpenAI) |
| `GROQ_API_KEY` | Groq Cloud | Token Bearer para LPUs de Groq (`provider="groq"`). | `None` (Requerido para Groq) |
| `DEEPSEEK_API_KEY` | DeepSeek | Token Bearer para la API de DeepSeek (`provider="deepseek"`). | `None` (Requerido para DeepSeek) |
| `XAI_API_KEY` | xAI Grok | Token Bearer para endpoints de xAI Grok (`provider="grok"`). | `None` (Requerido para Grok) |
| `GEMINI_API_KEY` | Google Gemini | Clave utilizada por el cliente `google-genai` de la versión estable v0.3.4. | `None` (Requerida para Gemini) |
| `GOOGLE_API_KEY` | Google Gemini | Clave alternativa disponible **sólo en v0.4.0rc1 prerelease**. | v0.3.4 no la lee |
| `GOOGLE_GEMINI_BASE_URL` | Google Gemini | URL de proxy personalizada disponible **sólo en v0.4.0rc1 prerelease**. | v0.3.4 no la lee |
| `ANTHROPIC_API_KEY` | Anthropic | Clave de API para la Messages API de Claude (`x-api-key`). | `None` (Requerido para Anthropic) |
| `OLLAMA_API_KEY` | Ollama | Token opcional para pasarelas autenticadas de Ollama. | `"ollama"` (Clave ficticia segura) |
| `{PROVIDER}_BASE_URL` | Preajustes compatibles con OpenAI | Anulación de la URL base que `OpenAIEngine` lee para su proveedor, p. ej. `OPENAI_BASE_URL`, `GROQ_BASE_URL`, `OLLAMA_BASE_URL`. Una URL remota no oficial requiere entonces una `api_key` explícita. | URL oficial del preajuste |

<Callout type="info" title="Gemini en Vertex AI en v0.3.4">
En v0.3.4, <code>GeminiEngine</code> lee <code>GEMINI_API_KEY</code> y la pasa al cliente <code>google-genai</code>. Cualquier otra gestión del entorno, incluida la configuración de Vertex AI (por ejemplo <code>GOOGLE_GENAI_USE_VERTEXAI</code>, <code>GOOGLE_CLOUD_PROJECT</code>, <code>GOOGLE_CLOUD_LOCATION</code>), la realiza el propio <code>google-genai</code>, no chatflow-agent; consulta la documentación de <code>google-genai</code> para la versión que tengas instalada. Vertex AI no es compatible con el motor basado en REST de <VersionBadge version="0.4.0rc1" status="prerelease" />.
</Callout>

## Ejemplo de Configuración en Producción

El enfoque recomendado para producción consiste en definir una clase de configuración fuertemente tipada (por ejemplo, con `dataclasses` o `pydantic-settings`) para validar todas las variables al arrancar el servicio:

```python
import os
from dataclasses import dataclass
from chatflow_agent import Agent, Runner
from chatflow_agent.core.memory import SQLiteSessionStore
from chatflow_agent.core.engines.openai_compatible import OpenAIEngine

@dataclass(frozen=True)
class AppConfig:
    """Validated application configuration."""
    database_path: str = os.getenv("CHATFLOW_DB_PATH", "production_sessions.db")
    max_tool_iterations: int = int(os.getenv("CHATFLOW_MAX_ITERATIONS", "8"))
    max_handoffs: int = int(os.getenv("CHATFLOW_MAX_HANDOFFS", "4"))
    llm_timeout: float = float(os.getenv("CHATFLOW_LLM_TIMEOUT", "45.0"))
    environment: str = os.getenv("ENVIRONMENT", "production")

config = AppConfig()

# Configurar motor con tiempo límite explícito para producción
production_engine = OpenAIEngine(
    api_key=os.environ.get("OPENAI_API_KEY"),
    provider="openai",
    timeout=config.llm_timeout,
)

# Configurar almacenamiento SQLite persistente
store = SQLiteSessionStore(
    db_path=config.database_path,
    default_max_turns=30,
)

support_agent = Agent(
    name="CustomerSupport",
    model="gpt-4o",
    engine=production_engine,
    instructions="Provide timely and professional customer service.",
)

runner = Runner(
    starting_agent=support_agent,
    session_store=store,
    max_tool_iterations=config.max_tool_iterations,
    max_handoffs_per_turn=config.max_handoffs,
)
```

## Manejo de Credenciales Sensibles en CI/CD

<Callout type="warn" title="Cero Fugas de Credenciales">
Nunca incluyas archivos `.env`, tokens de API o secretos en repositorios de Git. Añade siempre `.env`, `.env.*` y `*.db` a tu archivo `.gitignore`.
</Callout>

### Entradas Recomendadas para `.gitignore`

```bash
# Entorno y Secretos
.env
.env.local
.env.production
*.pem
*.key

# Bases de Datos Persistentes de Sesión
*.db
*.sqlite
*.sqlite3

# Bytecode y Caché de Python
__pycache__/
*.pyc
.venv/
```

### Plantilla de Archivo de Entorno (`.env.example`)

Mantén una plantilla sanitizada en tu repositorio para facilitar la incorporación del equipo de desarrollo:

```bash
# Proveedores de LLM
OPENAI_API_KEY="your-openai-api-key"
GROQ_API_KEY="your-groq-api-key"
GEMINI_API_KEY="your-gemini-api-key"
ANTHROPIC_API_KEY="your-anthropic-api-key"

# Configuración de la Aplicación
ENVIRONMENT="development"
CHATFLOW_DB_PATH="sessions.db"
CHATFLOW_LLM_TIMEOUT="45.0"
CHATFLOW_MAX_ITERATIONS="10"
CHATFLOW_MAX_HANDOFFS="5"
```
