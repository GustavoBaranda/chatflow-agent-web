Operar enjambres multi-agente en entornos de producción exige una visibilidad exhaustiva. Cuando un agente transfiere una conversación, invoca APIs externas o activa mecanismos de respaldo, los operadores requieren registros estructurados e IDs de correlación para diagnosticar latencias, investigar anomalías y auditar decisiones.

`chatflow-agent` v0.3.4 utiliza loggers de la biblioteca estándar de Python para el runner, los motores de proveedores y las integraciones de canales. La aplicación puede conectar su propio formateador estructurado.

## Jerarquía de Loggers

Todos los loggers se organizan bajo el espacio de nombres `chatflow_agent`. Puedes ajustar la verbosidad globalmente o de forma granular por componente:

```text
chatflow_agent
├── chatflow_agent.runner      (Fallos de ejecución de herramientas, con trace_id)
├── chatflow_agent.engine
│   ├── chatflow_agent.engine.openai     (Avisos de reintento: estado HTTP y errores de conexión)
│   ├── chatflow_agent.engine.gemini     (Avisos de reintento por errores transitorios de google-genai)
│   └── chatflow_agent.engine.anthropic  (Avisos de reintento: estado HTTP y errores de conexión)
├── chatflow_agent.telegram    (Inicio del polling, errores de permisos de /reset, errores de mensajes)
└── chatflow_agent.whatsapp    (Rechazos de firma, duplicados, tiempos límite, entrega saliente)
```

El SDK no emite métricas ni trazas, y los loggers de los motores no registran cargas útiles de las peticiones, latencias ni recuentos de tokens. Añade esa instrumentación en tu aplicación si la necesitas.

## Configuración de Registros Estructurados

En producción, formatea los registros como líneas individuales en JSON para que sistemas de ingestión centralizados (como Datadog, CloudWatch o Google Cloud Logging) indexen los campos automáticamente:

```python
import json
import logging
import sys
from chatflow_agent import Agent, Runner

class JSONLogFormatter(logging.Formatter):
    """Format log records as structured JSON."""
    def format(self, record: logging.LogRecord) -> str:
        log_entry = {
            "timestamp": self.formatTime(record, self.datefmt),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
            "module": record.module,
            "lineno": record.lineno,
        }
        if record.exc_info:
            log_entry["exception"] = self.formatException(record.exc_info)
        return json.dumps(log_entry)

def setup_production_logging(log_level: int = logging.INFO) -> None:
    """Initialize structured JSON logging for chatflow-agent."""
    handler = logging.StreamHandler(sys.stdout)
    handler.setFormatter(JSONLogFormatter())
    
    # Configurar logger raíz
    root_logger = logging.getLogger("chatflow_agent")
    root_logger.setLevel(log_level)
    root_logger.handlers = [handler]
    root_logger.propagate = False

if __name__ == "__main__":
    setup_production_logging()
    
    agent = Agent(name="ObservabilityBot", instructions="Test logging.")
    runner = Runner(starting_agent=agent)
    print("Structured logging configured.")
```

## Correlación de Trazas con `trace_id`

Cuando una herramienta falla durante la ejecución, el `Runner` genera automáticamente un UUID `trace_id` y lo adjunta tanto al registro interno como al mensaje entregado al agente:

```text
[ERROR] 2026-10-30T18:22:15Z chatflow_agent.runner: Tool execution failed [trace_id: 3c9b7e41-0f2d-4e92-bc12-f71e549d8802] - Tool: 'query_database' on agent 'BillingAgent': Error executing tool 'query_database': Connection timed out to db.internal.corp:5432
```

El registro se emite con `exc_info=True`, por lo que tu handler también recibe la traza de la pila.

### Importancia de la Correlación

1. **Privacidad del Usuario:** El modelo, y por tanto el usuario final, recibe solo el mensaje genérico con el `trace_id`, no el texto de la excepción ni direcciones internas.
2. **Triaje Determinista:** Cuando un usuario reporta *"Mi consulta falló a las 18:22"*, el equipo de soporte técnico puede buscar directamente `trace_id: 3c9b7e41...` en los registros para inspeccionar la excepción y su traza de la pila (*stack trace*). Los argumentos de la herramienta no se registran.

## Inspección de Telemetría de Respuesta

Cada invocación de `Runner.run()` o `Runner.run_async()` devuelve un objeto `AgentResponse` con metadatos de ejecución:

```python
from chatflow_agent import Agent, Runner

agent = Agent(name="Inspector", instructions="Provide analytical responses.")
runner = Runner(starting_agent=agent)

response = runner.run(
    session_id="session-user-99",
    user_message="Calculate quarterly forecast.",
)

# 1. Texto entregado al usuario
print(f"Content: {response.content}")

# 2. Agente activo final que formuló la respuesta
print(f"Active Agent: {response.active_agent_name}")

# 3. Lista de herramientas ejecutadas en este turno
print(f"Tools Executed: {response.tool_calls_executed}")

# 4. Detalles de transferencia si ocurrió un handoff
if response.handoff:
    print(f"Transferred to: {response.handoff.target_agent_name}")
    print(f"Reason: {response.handoff.reason}")
```

## Auditoría del Historial de Conversación

Para inspeccionar los turnos conversacionales almacenados en una sesión, recupera el contexto de la sesión directamente del almacenamiento configurado:

```python
from chatflow_agent import Agent, Runner
from chatflow_agent.core.memory import SessionStore

store = SessionStore()
agent = Agent(name="Support", instructions="Help customers.")
runner = Runner(starting_agent=agent, session_store=store)

# Ejecutar turno
runner.run(session_id="sess-42", user_message="Hello, I need assistance.")

# Inspeccionar sesión almacenada
session = store.get(session_id="sess-42")
if session:
    print(f"Total Messages: {len(session.history)}")
    for msg in session.history:
        print(f"[{msg.role.value}] {msg.content}")
```

<Callout type="warn" title="Datos Sensibles en los Registros">
<code>chatflow-agent</code> no instala ningún filtro ni mecanismo de redacción de registros. Sus motores no registran las cabeceras de las peticiones, por lo que las propias llamadas de registro del SDK no escriben claves de API, y <code>WhatsAppChannel</code> enmascara los números de teléfono en sus propios mensajes. Otro contenido aún puede llegar a tus registros: mensajes de excepción de las herramientas, cuerpos de error de los proveedores incluidos en <code>ProviderError</code> y respuestas de error de Meta. El registro por sí solo no hace que un despliegue cumpla con SOC 2, GDPR o marcos similares; añade filtros de redacción y políticas de retención acordes con tus requisitos.
</Callout>
