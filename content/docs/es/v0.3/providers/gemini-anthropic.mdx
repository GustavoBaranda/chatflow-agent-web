Google Gemini y Anthropic Claude representan dos familias de modelos potentes para flujos de trabajo basados en agentes. `chatflow-agent` v0.3.4 proporciona motores dedicados para ambos proveedores y utiliza sus clientes oficiales para admitir conversaciones de múltiples turnos y llamadas a herramientas.

---

## Motor Google Gemini

En la versión estable v0.3.4, `GeminiEngine` utiliza el cliente `google-genai` de Google para comunicarse con la API para desarrolladores de Gemini y ejecutar conversaciones de múltiples turnos y llamadas a funciones.

<Callout type="info" title="Variante de API de Gemini Soportada">
`GeminiEngine` es compatible con la **API de desarrolladores de Gemini** (claves de API de Google AI Studio). Google Cloud Vertex AI no está soportado por este motor.
</Callout>

### Autenticación y Credenciales

En la versión estable v0.3.4, el motor lee las credenciales desde las siguientes fuentes, en orden de prioridad:
1. `api_key` pasado directamente a `GeminiEngine(api_key="...")` o `Agent(api_key="...")`.
2. Variable de entorno `GEMINI_API_KEY`.

<Callout type="info" title="Opciones de credenciales en prerelease">
<VersionBadge version="0.4.0rc1" status="prerelease" /> agrega el fallback `GOOGLE_API_KEY` y la opción `api_key_in_query`. Estas opciones no están disponibles en la versión estable v0.3.4.
</Callout>

```python
import os
from chatflow_agent import Agent, Runner
from chatflow_agent.core.engines.gemini import GeminiEngine

# v0.3.4: la clave se pasa al cliente google-genai
gemini_engine = GeminiEngine(
    api_key=os.environ.get("GEMINI_API_KEY"),
    timeout_seconds=30.0,
    max_retries=3,
)

assistant = Agent(
    name="GeminiAssistant",
    model="gemini-2.5-flash",
    engine=gemini_engine,
    instructions="Provide concise, accurate answers.",
)
```

### Arquitectura del Motor Gemini por Versión

<div className="flex gap-2 my-3">
  <VersionBadge version="0.3.4" status="stable" />
  <VersionBadge version="0.4.0rc1" status="prerelease" />
</div>

La implementación de Gemini experimentó una evolución arquitectónica entre versiones:

* **En `v0.3.4` (Estable):** El motor usa el SDK oficial `google-genai` de Google (`from google import genai`), que se instala automáticamente como dependencia principal. No hay pool de conexiones.
* **En `v0.4.0rc1` (Pre-lanzamiento):** El motor fue reescrito utilizando `httpx` asíncrono nativo contra `https://generativelanguage.googleapis.com/v1beta`. Esto elimina la dependencia de `google-genai` y, dentro de un ámbito `async with runner:`, permite que las peticiones a Gemini compartan un único cliente HTTP con pool de conexiones.

En v0.3.4, ejecuta los turnos directamente sobre un runner compartido:

```python
# [no-exec: requires real gemini api key]
import asyncio
from chatflow_agent import Agent, Runner

agent = Agent(
    name="Assistant",
    instructions="Provide concise, accurate answers.",
    model="gemini-2.5-flash",
)
runner = Runner(starting_agent=agent)

async def main():
    # En v0.3.x, ejecuta turnos asíncronos directamente sobre el runner
    res1 = await runner.run_async("session-1", "What is quantum computing?")
    res2 = await runner.run_async("session-1", "Summarize in 3 bullet points.")
    print(res2.content)

asyncio.run(main())
```

### Configuración de Proxies Personalizados (Prerelease)

<VersionBadge version="0.4.0rc1" status="prerelease" /> Para enrutar peticiones de Gemini mediante un proxy corporativo en la prerelease, define `GOOGLE_GEMINI_BASE_URL`. La versión estable v0.3.4 no admite esta variable:

```bash
export GOOGLE_GEMINI_BASE_URL="https://gemini-proxy.internal.corp"
```
El motor v0.4.0rc1 añade automáticamente `/v1beta` a la URL base.

## Motor Anthropic Claude

`AnthropicEngine` proporciona integración nativa con Claude 3.5 Sonnet, Claude 3.5 Haiku y Claude 3 Opus de Anthropic a través de la Messages API.

### Autenticación y Cabeceras

Las peticiones a Anthropic requieren la cabecera `x-api-key` y la cabecera `anthropic-version` (por defecto `"2023-06-01"`).

El motor lee las credenciales de:
1. `api_key` pasado explícitamente a `AnthropicEngine(api_key="...")` o `Agent(api_key="...")`.
2. Variable de entorno `ANTHROPIC_API_KEY`.

<Callout type="warn" title="Regla de Seguridad de Credenciales">
Al igual que `OpenAIEngine`, `AnthropicEngine` solo transmite `ANTHROPIC_API_KEY` al endpoint oficial `https://api.anthropic.com/v1`. Si especificas un `base_url` personalizado, debes suministrar `api_key` de forma explícita.
</Callout>

```python
import os
from chatflow_agent import Agent
from chatflow_agent.core.engines.anthropic import AnthropicEngine

claude_engine = AnthropicEngine(
    api_key=os.environ.get("ANTHROPIC_API_KEY"),
    timeout=60.0,
)

editor = Agent(
    name="Editor",
    model="claude-3-5-sonnet-20241022",
    engine=claude_engine,
    instructions="Edit and refine technical documentation.",
)
```

### Reintentos Automáticos y Retroceso con Jitter

`AnthropicEngine` reintenta automáticamente los límites de tasa (`429 Too Many Requests`), los errores temporales del servidor (`500`, `502`, `503`, `504`), el estado de sobrecarga de Anthropic (`529`) y los errores de conexión, mediante retroceso exponencial con jitter:
* **Reintentos Máximos:** 3 reintentos tras el primer intento (hasta 4 peticiones).
* **Demora Base:** 1.0 segundo.
* **Demora Máxima:** 10.0 segundos.

Estos valores son fijos en v0.3.4; no son parámetros del constructor. Cuando una respuesta reintentada incluye una cabecera `Retry-After` numérica, ese valor sustituye a la demora exponencial, pero la espera sigue limitada a 10 segundos, por lo que un retraso solicitado mayor no se respeta por completo.

## Colaboración Multimodelo entre Agentes

Una ventaja clave de `chatflow-agent` es componer enjambres donde distintos agentes emplean diferentes modelos fundacionales según sus fortalezas:

```python
from chatflow_agent import Agent, Runner
from chatflow_agent.core.engines.gemini import GeminiEngine
from chatflow_agent.core.engines.anthropic import AnthropicEngine

gemini = GeminiEngine()
claude = AnthropicEngine()

researcher = Agent(
    name="Researcher",
    model="gemini-2.5-flash",
    engine=gemini,
    instructions="Gather facts quickly using Gemini's high-throughput processing.",
)

synthesizer = Agent(
    name="Synthesizer",
    model="claude-3-5-sonnet-20241022",
    engine=claude,
    instructions="Synthesize gathered facts into clear, well-structured prose.",
)

# Conectar agentes mediante handoffs
researcher.add_handoff(synthesizer)
synthesizer.add_handoff(researcher)

runner = Runner(starting_agent=researcher)
```

En este enjambre:
1. El **Investigador** se ejecuta sobre Gemini 2.5 Flash para ingestión y búsqueda de alto rendimiento.
2. Una vez recopilados los datos, la sesión se transfiere al **Sintetizador** sobre Claude 3.5 Sonnet.
3. <VersionBadge version="0.4.0rc1" status="prerelease" /> En la prerelease se normalizan los mensajes históricos y los IDs de llamadas a herramientas. La versión estable v0.3.4 no ofrece esta garantía.
