`chatflow-agent` está construido alrededor de cinco abstracciones componibles. Entender cómo interactúan facilita diseñar desde un chatbot con herramientas hasta un enjambre multi-proveedor.

## 1. `Agent` — Persona, Herramientas y Reglas de Enrutamiento

Un `Agent` (`chatflow_agent.core.agent.Agent`) es un objeto declarativo que representa a un especialista de IA. Un agente **no** almacena estado conversacional; define:

* **`name`** (`str`): Identificador único dentro de un enjambre (ej. `"TriageAgent"`, `"BillingSpecialist"`). Se utiliza para sintetizar herramientas de handoff (`transfer_to_billingspecialist`).
* **`instructions`** (`str | Callable[[], str]`): El prompt del sistema — una cadena estática o una función sin argumentos evaluada dinámicamente al inicio de cada turno.
* **`model`** (`str`): Identificador del modelo (por defecto `"gemini-2.5-flash"`).
* **`tools`** (`list[Tool | Callable]`): Funciones autorizadas que el agente puede invocar, validadas en tiempo de ejecución con Pydantic (`validate_args=True` por defecto).
* **`handoffs`** (`list[Agent]`): Agentes destino a los que este agente puede delegar la conversación.
* **`provider` / `base_url` / `api_key` / `engine`**: Anulaciones opcionales de enrutamiento para que cada agente de un enjambre opere con un proveedor LLM distinto. Los nombres de proveedor inválidos o la falta de credenciales en endpoints remotos personalizados fallan inmediatamente con `ConfigurationError`.

```python
# [executable]
from datetime import datetime, timezone
from chatflow_agent import Agent

def dynamic_prompt() -> str:
    now = datetime.now(timezone.utc).strftime("%Y-%m-%d %H:%M UTC")
    return f"You are a support specialist. Current server time: {now}."

agent = Agent(
    name="SupportSpecialist",
    instructions=dynamic_prompt,
    model="gpt-4o",
)

assert "Current server time:" in agent.get_instructions()
```

## 2. `Runner` — El Orquestador de Turnos

El `Runner` (`chatflow_agent.core.runner.Runner`) coordina la ejecución entre sesiones, agentes, motores y herramientas:

1. **Descubrimiento del Registro de Agentes:** Al inicializarse, `Runner` realiza un recorrido BFS desde `starting_agent` sobre todas las aristas `.handoffs` registrando cada `Agent` alcanzable. Si dos instancias distintas de `Agent` comparten el mismo `.name`, `Runner` lanza `ValueError` inmediatamente.
2. **Bloqueo de Concurrencia por Sesión:** Las llamadas a `run_async()` para un mismo `session_id` adquieren un `asyncio.Lock` dedicado para evitar corrupción del historial. En `v0.4.0`, si una herramienta o tarea en segundo plano iniciada dentro de un turno intenta llamar a `run()` o `run_async()` sobre el **mismo** `session_id`, `Runner` lanza `ReentrantTurnError` de inmediato en lugar de sufrir un interbloqueo.
3. **Reinicio Seguro de Sesión (`reset_session_async`):** `await runner.reset_session_async(session_id) -> bool` y `runner.reset_session(session_id) -> bool` coordinan el borrado del historial con el bloqueo de turno, la barrera de trabajo síncrono y la guarda de reentrancia, devolviendo `True` si existía una sesión y fue limpiada, o `False` en caso contrario.
4. **Bucle de Ejecución Acotado:** Dentro de un turno, `Runner` aplica `max_tool_iterations` (por defecto `10`) y `max_handoffs_per_turn` (por defecto `5`) para evitar bucles infinitos.
5. **Reversión Transaccional de Turno:** Si un motor lanza `ProviderError`, falla un handoff, o el turno es cancelado o excede `turn_timeout`, `Runner` restaura el historial de mensajes, `active_agent` y `metadata` al estado exacto previo al turno.

## 3. `BaseEngine` — Inferencia LLM Intercambiable

Los motores (`chatflow_agent.core.engines.base.BaseEngine`) implementan un único contrato asíncrono:

```python
async def generate_turn_async(
    self,
    agent: Agent,
    history: list[Message],
) -> EngineTurnResult:
    ...
```

De serie, `chatflow-agent` incluye tres motores de producción — todos basados en `httpx.AsyncClient` sin dependencias pesadas de SDKs de proveedores:

* **`GeminiEngine`**: Se comunica directamente con la API REST de Google Gemini (`https://generativelanguage.googleapis.com/v1beta`), con backoff exponencial automático, soporte para `Retry-After`, IDs sintéticos resistentes a colisiones (`cf_gemini_<24 hex>`) y redacción de claves API.
* **`OpenAIEngine`**: Soporta OpenAI (`https://api.openai.com/v1`) además de presets integrados para `deepseek`, `groq`, `grok` y `ollama` local, con IDs sintéticos sin estado (`call_<24 hex>`).
* **`AnthropicEngine`**: Se conecta a la API de Mensajes de Anthropic (`/v1/messages`) con traducción nativa de bloques `tool_use` / `tool_result` y `max_tokens: int = 4096` configurable.

## 4. `Tool` y `@tool` — Llamada a Funciones Validada

Un `Tool` (`chatflow_agent.core.tools.Tool`) envuelve una función Python síncrona o asíncrona:

* Inspecciona anotaciones de tipo en Python (`str`, `int`, `float`, `bool`, `list[T]`, `Sequence[T]`, `set[T]`, `frozenset[T]`, `tuple[T, ...]`, `dict`, `Optional[T]` / `T | None`, uniones de tipos soportados y `Annotated[T, ...]`) para compilar esquemas de function-calling. Lanza `ToolSchemaError` al definirse si una anotación de unión contiene un miembro sin mapeo (ej. `CustomClass | None`), mientras que los tipos no-unión no soportados conservan el fallback compatible `STRING` / `string`.
* Valida y coacciona los argumentos del modelo en tiempo de ejecución antes de invocar la función (`validate_args=True` por defecto), lanzando `ToolArgumentValidationError` (subclase de `ToolExecutionError`) ante argumentos inválidos.
* Despacha funciones síncronas y espera corutinas (`inspect.iscoroutinefunction`).
* Si una herramienta lanza una excepción en ejecución, `Runner` la captura, registra un `trace_id` con traza en el log y devuelve un `ToolResult` saneado (`is_error=True`) al LLM sin filtrar stack traces a los usuarios.

## 5. `BaseSessionStore` y `SessionContext` — Estado y Memoria

El estado conversacional se encapsula en `SessionContext`:

* **`session_id`** (`str`): Clave única de conversación (ej. número de WhatsApp, chat ID de Telegram o UUID).
* **`history`** (`list[Message]`): Secuencia ordenada de mensajes `USER`, `ASSISTANT`, `TOOL` y `SYSTEM`, acotada por ventana deslizante (`max_turns`, por defecto `50` turnos de usuario) que preserva pares de llamadas a herramientas y un ancla `[System Note]`.
* **`active_agent`** (`Agent`): Agente que atiende actualmente la sesión; se actualiza y persiste tras cada handoff.
* **`metadata`** (`dict[str, Any]`): Diccionario JSON-serializable persistido junto a la sesión (con aislamiento por copia profunda en `SessionStore`, serialización ISO-8601 para `datetime`/`date`/`time` y `JsonCodecError` para objetos no serializables).

Elige entre:
* **`SessionStore`**: Almacén rápido en memoria con aislamiento por copia profunda de metadatos y deduplicación thread-safe.
* **`SQLiteSessionStore`**: Almacén duradero en SQLite con journaling `WAL`, soporte `:memory:` persistente, lecturas en una sola transacción, reversión transaccional de turnos y deduplicación de webhooks de 192 horas (`8 días`).
