`chatflow-agent` se distribuye en [PyPI](https://pypi.org/project/chatflow-agent/) con un núcleo mínimo. En **`v0.4.0`**, el paquete principal depende únicamente de **`pydantic>=2.6.0`** y **`httpx>=0.27.0,<1.0`** (`google-genai` se eliminó en `v0.4.0` porque `GeminiEngine` ahora llama directamente a la API REST de Gemini sobre `httpx.AsyncClient`). Las integraciones de canales (`telegram`, `whatsapp`, `webhook`) se ofrecen como extras opcionales para mantener ligeros los contenedores de producción.

## Requisitos del Sistema

* **Python:** `>= 3.10` (`Requires-Python: >=3.10`; probado en Python 3.10, 3.11, 3.12 y 3.13)
* **Gestores de Paquetes:** `pip`, `uv` o `poetry`
* **Sistemas Operativos:** La CI del SDK se ejecuta en Linux (Ubuntu) y Windows. Al ser Python puro sin marcadores de plataforma, se espera que funcione en macOS y arm64 aunque no formen parte de la matriz de CI.
* **Dependencias Principales (Instaladas Automáticamente):**
  * `pydantic >= 2.6.0` (Validación de datos, validación de argumentos de herramientas en tiempo de ejecución y helpers de esquema)
  * `httpx >= 0.27.0, < 1.0` (Transporte HTTP asíncrono para OpenAI, Gemini, Anthropic, Ollama y WhatsApp)
  * La persistencia en SQLite utiliza la biblioteca integrada `sqlite3` de Python sin controladores de terceros.

## Matriz de Dependencias Principales y Extras Opcionales

La tabla siguiente refleja exactamente los metadatos (`Requires-Dist` y `Provides-Extra`) publicados en la wheel **`chatflow-agent==0.4.0`**:

| Línea / Extra | Comando de Instalación | Paquetes Añadidos | Requerido Por |
| :--- | :--- | :--- | :--- |
| *(Core — siempre instalado)* | `pip install chatflow-agent==0.4.0` | `pydantic>=2.6.0`, `httpx>=0.27.0,<1.0` | `Agent`, `Runner`, `OpenAIEngine`, `GeminiEngine`, `AnthropicEngine`, `SessionStore`, `SQLiteSessionStore`, `CLIChannel` |
| `telegram` | `pip install "chatflow-agent[telegram]==0.4.0"` | `python-telegram-bot>=21.0` | `TelegramChannel` |
| `whatsapp` | `pip install "chatflow-agent[whatsapp]==0.4.0"` | `fastapi>=0.110.0`, `uvicorn>=0.29.0` | `WhatsAppChannel` |
| `webhook` | `pip install "chatflow-agent[webhook]==0.4.0"` | `fastapi>=0.110.0`, `uvicorn>=0.29.0` | Endpoints HTTP FastAPI personalizados (no existe un canal genérico integrado; consulta [Webhooks Personalizados](/es/docs/v0.4/integrations/webhook)) |
| `all` | `pip install "chatflow-agent[all]==0.4.0"` | `python-telegram-bot>=21.0`, `fastapi>=0.110.0`, `uvicorn>=0.29.0` | Despliegues multicanal completos |
| `dev` | `pip install "chatflow-agent[dev]==0.4.0"` | `pytest>=8.0.0`, `pytest-asyncio>=0.23.0`, `ruff>=0.4.0`, `mypy>=1.9.0` | Contribuir y ejecutar la suite de pruebas del SDK |

<Callout type="info" title="Importaciones Perezosas de Canales y DependencyError">
Si intentas instanciar `TelegramChannel` o `WhatsAppChannel` sin instalar su extra correspondiente, `chatflow-agent` lanza un `DependencyError` descriptivo con el comando `pip install` exacto necesario.
</Callout>

## Configuración de Claves de API de Proveedores

`chatflow-agent` resuelve automáticamente las credenciales desde variables de entorno estándar cuando no se pasa `api_key` explícitamente al constructor de un `Agent` o motor. Cada proveedor lee únicamente su propia variable y solo cuando la petición se dirige a su endpoint oficial (`OPENAI_API_KEY` nunca se envía a otro proveedor ni a un host remoto personalizado):

| Proveedor | Variable de Entorno | Modelo de Ejemplo | Clase de Motor |
| :--- | :--- | :--- | :--- |
| **Google Gemini** | `GEMINI_API_KEY` *(usa `GOOGLE_API_KEY` como respaldo si no está definida; opcional `GOOGLE_GEMINI_BASE_URL` para proxies)* | `gemini-2.5-flash` | `GeminiEngine` |
| **OpenAI** | `OPENAI_API_KEY` | `gpt-4o-mini` | `OpenAIEngine` |
| **Anthropic** | `ANTHROPIC_API_KEY` | `claude-3-5-sonnet-latest` | `AnthropicEngine` |
| **DeepSeek** | `DEEPSEEK_API_KEY` | `deepseek-chat` | `OpenAIEngine(provider="deepseek")` |
| **Groq** | `GROQ_API_KEY` | `llama-3.3-70b-versatile` | `OpenAIEngine(provider="groq")` |
| **xAI Grok** (`provider="grok"` o `"xai"`) | `XAI_API_KEY` | `grok-2` | `OpenAIEngine(provider="grok")` |
| **Ollama / Gemma (Local)** (`provider="ollama"` o `"gemma"`) | `OLLAMA_API_KEY` *(opcional; un servidor Ollama local no requiere clave)* | `gemma2:9b` | `OpenAIEngine(provider="ollama")` |

Exporta las variables en tu terminal antes de iniciar la aplicación:

<Tabs items={['Linux / macOS (bash/zsh)', 'Windows (PowerShell)']}>
  <Tab value="Linux / macOS (bash/zsh)">
```bash
export OPENAI_API_KEY="sk-..."
export GEMINI_API_KEY="AIza..."
export ANTHROPIC_API_KEY="sk-ant-..."
export XAI_API_KEY="xai-..."
export DEEPSEEK_API_KEY="sk-..."
export GROQ_API_KEY="gsk_..."
```
  </Tab>
  <Tab value="Windows (PowerShell)">
```powershell
$env:OPENAI_API_KEY="sk-..."
$env:GEMINI_API_KEY="AIza..."
$env:ANTHROPIC_API_KEY="sk-ant-..."
$env:XAI_API_KEY="xai-..."
```
  </Tab>
</Tabs>
