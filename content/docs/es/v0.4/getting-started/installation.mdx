## Requisitos Previos

Antes de instalar `chatflow-agent`, asegúrate de que tu sistema cumpla con los requisitos mínimos de Python:

* **Versión de Python:** Python `>=3.10` (probado en 3.10, 3.11, 3.12 y 3.13).
* **Gestor de Paquetes:** `pip`, `uv` o `poetry`.
* **Sistemas Operativos:** la CI del SDK se ejecuta en Linux (Ubuntu) y Windows. El paquete es Python puro, por lo que se espera que funcione en macOS y arm64, pero no forman parte de la matriz de CI.

Verifica la versión local de Python en tu terminal:

```bash
python --version
# La salida debe indicar Python 3.10.x o superior
```

## Instalación del Paquete Central

En v0.4.0rc1, el núcleo depende únicamente de `pydantic` y `httpx`; no se requiere ningún SDK de proveedor. Esta versión de la documentación cubre la versión candidata publicada `0.4.0rc1`. Para producción, utiliza la versión estable `0.3.4`:

<Tabs items={['pip', 'uv', 'poetry']}>
  <Tab value="pip">
```bash
# Instalar la versión estable actual (v0.3.4 - recomendada para producción)
pip install chatflow-agent

# O instalar la versión preliminar candidata documentada aquí (fija la versión exacta)
pip install "chatflow-agent==0.4.0rc1"
```
  </Tab>
  <Tab value="uv">
```bash
# Instalar la versión estable actual con uv
uv add chatflow-agent

# O instalar la versión preliminar candidata documentada aquí
uv add "chatflow-agent==0.4.0rc1"
```
  </Tab>
  <Tab value="poetry">
```bash
# Instalar la versión estable actual con poetry
poetry add chatflow-agent

# O instalar la versión preliminar candidata
poetry add chatflow-agent@0.4.0rc1
```
  </Tab>
</Tabs>

<Callout type="info" title="Sin Bloqueo de SDKs y Dependencias Centrales">
En **v0.4.0rc1**, las dependencias centrales son `pydantic>=2.6.0` y `httpx>=0.27.0`: `google-genai` ya no es una dependencia, y los motores de Gemini, Anthropic y compatibles con OpenAI llaman a sus API REST mediante `httpx`. En la versión estable **v0.3.4**, el núcleo también depende de `google-genai>=0.1.1`, que utiliza `GeminiEngine`. La persistencia en SQLite utiliza la biblioteca integrada `sqlite3` de Python sin controladores de base de datos de terceros.
</Callout>

## Extras Opcionales de Canales

`chatflow-agent` declara dependencias opcionales en `pyproject.toml` para mantener un tamaño base mínimo. Instala únicamente las capacidades requeridas por tu despliegue:

| Nombre del Extra | Descripción | Dependencias Clave Añadidas | Comando |
| :--- | :--- | :--- | :--- |
| `[telegram]` | Integración con bots de Telegram mediante long polling (`TelegramChannel`) | `python-telegram-bot>=21.0` | `pip install "chatflow-agent[telegram]==0.4.0rc1"` |
| `[whatsapp]` | Servidor webhook para la API Cloud de WhatsApp de Meta (`WhatsAppChannel`) | `fastapi>=0.110.0`, `uvicorn>=0.29.0` | `pip install "chatflow-agent[whatsapp]==0.4.0rc1"` |
| `[webhook]` | Instala FastAPI y Uvicorn para construir tu propio endpoint HTTP. No existe un canal de webhook genérico integrado; consulta la [guía de Webhooks Personalizados](/es/docs/v0.4/integrations/webhook) | `fastapi>=0.110.0`, `uvicorn>=0.29.0` | `pip install "chatflow-agent[webhook]==0.4.0rc1"` |
| `[all]` | Instala todas las dependencias de canales simultáneamente | `telegram`, `whatsapp`, `webhook` | `pip install "chatflow-agent[all]==0.4.0rc1"` |
| `[dev]` | Herramientas para ejecutar suites de pruebas unitarias e integración | `pytest>=8.0.0`, `pytest-asyncio`, `ruff`, `mypy` | `pip install "chatflow-agent[dev]==0.4.0rc1"` |

## Verificación

Confirma que `chatflow-agent` esté instalado correctamente comprobando su versión en Python:

```bash
python -c "import chatflow_agent; print(chatflow_agent.__version__)"
```

Salida esperada para esta versión de la documentación:
```text
0.4.0rc1
```
*(`0.3.4` si instalaste la versión estable)*.

## Configuración de Claves de API de Proveedores

Para interactuar con LLMs, exporta la clave de API del proveedor seleccionado como variable de entorno en tu terminal o archivo `.env`. Cada proveedor lee su propia variable, y solo cuando la petición se dirige al endpoint oficial de ese proveedor; `OPENAI_API_KEY` nunca se envía a otro proveedor o host:

```bash
# OpenAI
export OPENAI_API_KEY="sk-..."

# xAI Grok (provider="grok" o provider="xai")
export XAI_API_KEY="xai-..."

# DeepSeek y Groq
export DEEPSEEK_API_KEY="sk-..."
export GROQ_API_KEY="gsk_..."

# Modelos Anthropic Claude
export ANTHROPIC_API_KEY="sk-ant-..."

# Modelos Google Gemini (se usa GOOGLE_API_KEY si GEMINI_API_KEY no está definida)
export GEMINI_API_KEY="AIzaSy..."

# Un servidor Ollama local no necesita clave. OLLAMA_API_KEY solo se usa si la defines.
```

En Windows PowerShell:
```powershell
$env:OPENAI_API_KEY="sk-..."
$env:ANTHROPIC_API_KEY="sk-ant-..."
$env:GEMINI_API_KEY="AIzaSy..."
```
