Las herramientas permiten a los agentes interactuar con entornos externos, realizar cálculos, consultar bases de datos y desencadenar acciones de negocio. En **chatflow-agent**, las herramientas son objetos de primer nivel creados mediante el decorador `@tool` o instanciados directamente con la clase `Tool`.

El framework inspecciona la firma de cada herramienta y genera el esquema que necesita cada proveedor (declaraciones de Gemini, y JSON Schema para OpenAI y Anthropic): los tipos de los parámetros provienen de las anotaciones de tipo de Python, y los parámetros opcionales, de sus valores por defecto. La descripción de la herramienta es el argumento `description=`, o el docstring de la función cuando no se proporciona. Las secciones del docstring como `Args:` no se procesan para generar descripciones por parámetro. No es necesario redactar esquemas manuales.

## Definición de Herramientas con `@tool`

La forma estándar de crear una herramienta es mediante el decorador `@tool`. Puedes aplicarlo de forma directa o personalizar su nombre y descripción:

### 1. Decorador Simple
Infiere el nombre de la herramienta a partir del identificador de la función y la descripción desde su docstring:

```python
# [min-version: 0.3.0]
# [executable]
from chatflow_agent import tool

@tool
def calculate_vat(subtotal: float, rate: float = 0.20) -> float:
    """Calculate Value-Added Tax for an order subtotal."""
    return round(subtotal * rate, 2)

assert calculate_vat.name == "calculate_vat"
assert "Calculate Value-Added Tax" in calculate_vat.description
```

### 2. Decorador Parametrizado
Sobrescribe explícitamente el nombre y la descripción expuestos al LLM:

```python
# [min-version: 0.3.0]
# [executable]
from chatflow_agent import tool

@tool(
    name="lookup_stock_ticker",
    description="Fetch the latest real-time market quote for a stock symbol.",
)
def fetch_quote(symbol: str) -> dict:
    """Internal function to retrieve stock prices."""
    # Consultar servicio financiero
    return {"symbol": symbol.upper(), "price": 182.50, "currency": "USD"}

assert fetch_quote.name == "lookup_stock_ticker"
```

## Mapeo de Tipos e Introspección de Esquemas de Parámetros

Cuando se registra una herramienta, `chatflow-agent` inspecciona su firma mediante el módulo estándar `inspect` de Python y genera un esquema de parámetros:

| Anotación en Python | Tipo Canónico del Esquema | Requerido Si |
| :--- | :--- | :--- |
| `str` | `"STRING"` | No tiene valor predeterminado |
| `int` | `"INTEGER"` | No tiene valor predeterminado |
| `float` | `"NUMBER"` | No tiene valor predeterminado |
| `bool` | `"BOOLEAN"` | No tiene valor predeterminado |
| `list` | `"ARRAY"` | No tiene valor predeterminado |
| `dict` | `"OBJECT"` | No tiene valor predeterminado |
| *Sin anotar* / `Any` | `"STRING"` (Fallback) | No tiene valor predeterminado |

Los parámetros con valores predeterminados (ej. `rate: float = 0.20`) se marcan como opcionales en el esquema, mientras que los que carecen de valores por defecto se incluyen en el array `required`.

<Callout type="tip" title="Buenas Prácticas en Docstrings">
Los modelos de lenguaje deciden si invocar una herramienta basándose en su nombre y descripción. Escribe siempre docstrings concisos y claros que detallen el propósito exacto y los argumentos esperados.
</Callout>

## Ejecución Síncrona vs. Asíncrona de Herramientas

`chatflow-agent` fue diseñado bajo el principio async-first, pero admite indistintamente funciones de herramientas síncronas (`def`) y asíncronas (`async def`).

```python
import asyncio
from chatflow_agent import tool

# Herramienta síncrona
@tool
def sync_reverse(text: str) -> str:
    """Reverse a string synchronously."""
    return text[::-1]

# Herramienta asíncrona
@tool
async def async_fetch_status(service_name: str) -> dict:
    """Query service health asynchronously without blocking."""
    await asyncio.sleep(0.01)  # Simula E/S de red asíncrona
    return {"service": service_name, "status": "healthy"}
```

### Métodos de Ejecución

* **`await tool.execute_async(**kwargs)` (Recomendado):**
  * Si la herramienta es `async def`, se espera directamente en el bucle de eventos actual.
  * Si la herramienta es síncrona `def`, se delega automáticamente a un hilo trabajador mediante `asyncio.to_thread`. Esto asegura que cálculos intensivos, lecturas en disco o librerías bloqueantes de red nunca congelen el bucle de eventos principal.
* **`tool.execute(**kwargs)` (Conveniencia Síncrona):**
  * Ejecuta directamente herramientas síncronas.
  * Si se invoca sobre una herramienta `async def` fuera de un bucle de eventos, la ejecuta utilizando `asyncio.run()`.

<Callout type="warn" title="Protección del Bucle de Eventos">
Invocar <code>tool.execute()</code> de forma síncrona sobre una herramienta <code>async def</code> desde dentro de un bucle de eventos en ejecución (ej. en FastAPI, manejadores de Telegram o turnos del Runner) no está soportado. La llamada lanza <code>ToolExecutionError</code>, cuyo <code>original_error</code> es un <code>RuntimeError</code>; un bloque <code>except RuntimeError</code> no lo captura. Utiliza siempre <code>await tool.execute_async()</code> en código asíncrono.
</Callout>

## Diferencias de Versión y Funciones Preliminares

La generación de esquemas y la ejecución de herramientas presentan mejoras sustanciales entre versiones:

### Versión Estable (`v0.3.4`)
* <VersionBadge version="0.3.4" status="stable" /> Formato de declaración canónico para Gemini (`to_gemini_declaration()`).
* Mapeo de tipos de un solo nivel para tipos primitivos y `list`/`dict` sin parametrizar.
* Funciones síncronas delegadas mediante `asyncio.to_thread` durante `execute_async()`.

### Mejoras de la Versión Preliminar (`v0.4.0rc1`)
* <VersionBadge version="0.4.0rc1" status="prerelease" /> **Tipado Profundo de Colecciones:** Inspecciona esquemas de elementos internos para `list[T]`, `Sequence[T]`, `set[T]` y tuplas homogéneas `tuple[T, ...]`:

```python
from chatflow_agent import tool

@tool
def sum_metrics(values: list[float]) -> float:
    """Sum a list of numeric measurements."""
    return sum(values)

# Genera: {"type": "ARRAY", "items": {"type": "NUMBER"}}
```

* <VersionBadge version="0.4.0rc1" status="prerelease" /> **Soporte para Union y Optional:**
  * `Optional[T]` o `T | None` genera `{ "type": "...", "nullable": True }`.
  * `int | float` se amplía de forma determinista a `"NUMBER"` sin importar el orden de declaración.
  * Uniones de múltiples tipos generan una lista de esquemas `anyOf`.
* <VersionBadge version="0.4.0rc1" status="prerelease" /> **`to_openai_parameters()`:** Genera parámetros con formato JSON Schema (nombres de tipo en minúsculas, `type: "null"` y sin la clave `nullable`) para motores de OpenAI y Anthropic.
* <VersionBadge version="0.4.0rc1" status="prerelease" /> **`ToolSchemaError`:** Se lanza al crear la herramienta si una anotación de unión contiene un miembro sin mapeo de esquema (por ejemplo, `int | datetime`). Las demás anotaciones desconocidas, y los parámetros sin anotar, siguen recurriendo a `"STRING"`.
* <VersionBadge version="0.4.0rc1" status="prerelease" /> **Exclusión de Argumentos Variables:** `*args` y `**kwargs` se omiten automáticamente de los esquemas de parámetros.

## Aislamiento de Errores y Tolerancia a Fallos

En producción, las herramientas pueden experimentar tiempos de espera de red, consultas inválidas a base de datos o excepciones imprevistas.

`chatflow-agent` aísla los fallos de las herramientas dentro del turno de ejecución. Si una herramienta lanza una excepción no controlada durante su ejecución:

1. La excepción se intercepta y se envuelve en un `ToolExecutionError`.
2. El `Runner` captura la falla e inyecta un `ToolResult` en el historial de la conversación marcado con `is_error=True`:
   ```python
   # Inyectado en el historial de mensajes para el LLM:
   # ToolResult(tool_call_id="call_123", name="query_db", content="Tool execution failed [trace_id: ...]. Please try a different approach or inform the user.", is_error=True)
   ```
3. La excepción original se escribe en el log `chatflow_agent.runner` con el mismo `trace_id`; no se expone al modelo. En lugar de interrumpir la conversación, el agente activo recibe únicamente el error genérico y puede intentar otro enfoque, informar al usuario o transferir a una cola de soporte humano. Si el modelo necesita una explicación específica, haz que la herramienta **devuelva** un mensaje breve y seguro para el usuario en lugar de lanzar una excepción.

## Ejemplo Completo: Agente con Múltiples Herramientas

```python
from chatflow_agent import Agent, Runner, tool
from chatflow_agent.core.memory import SessionStore

# 1. Definir herramientas modulares de dominio
@tool
def calculate_shipping(weight_kg: float, destination: str) -> dict:
    """Calculate shipping estimate based on weight and country destination."""
    rate_per_kg = 8.50 if destination.upper() in ["US", "CA"] else 14.00
    total = round(weight_kg * rate_per_kg, 2)
    return {"destination": destination.upper(), "cost_usd": total, "delivery_days": 3}

@tool
def check_inventory(sku: str) -> dict:
    """Check stock availability for a product SKU."""
    return {"sku": sku, "in_stock": True, "warehouse": "east-region-1"}

# 2. Vincular herramientas al agente
logistics_agent = Agent(
    name="LogisticsCoordinator",
    instructions="Help customers check inventory availability and calculate shipping rates.",
    tools=[calculate_shipping, check_inventory],
    model="gemini-2.5-flash",
)

# 3. Crear runner con almacenamiento de sesiones
store = SessionStore()
runner = Runner(starting_agent=logistics_agent, session_store=store)

# 4. Ejecutar turno
response = runner.run(
    session_id="customer-turn-42",
    user_message="Can you check stock for SKU-990 and estimate shipping 2.5 kg to CA?",
)
print("Agent Response:", response.content)
print("Tools Executed:", response.tool_calls_executed)
```

## Errores Comunes y Anti-Patrones

### 1. Olvidar Anotaciones de Tipo
Los parámetros sin anotaciones de tipo se interpretan por defecto como `"STRING"`. Si tu herramienta espera números o booleanos, incluye siempre pistas de tipo:
```python
# [INCORRECTO]: "count" se expondrá como STRING, requiriendo conversión manual a int
@tool
def repeat_phrase(phrase, count): ...

# [CORRECTO]: Parámetros fuertemente tipados generan validación OpenAPI exacta
@tool
def repeat_phrase(phrase: str, count: int) -> str:
    return phrase * count
```

### 2. Operaciones Bloqueantes de Red en Herramientas Síncronas
Aunque las herramientas síncronas se delegan a hilos de trabajo mediante `asyncio.to_thread`, operaciones bloqueantes de red sin tiempos límite pueden agotar el grupo de hilos de Python. Siempre que sea posible, escribe herramientas de E/S de red utilizando `async def` con tiempos límite explícitos.

### 3. Modificar Estado Global en Funciones de Herramientas
Las herramientas deben ser funciones puras o interactuar con almacenamiento externo a través de clientes thread-safe. Evita modificar variables globales, ya que múltiples sesiones de usuario pueden invocar la misma herramienta de forma concurrente.
