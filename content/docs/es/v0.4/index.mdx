Bienvenido a la documentación preliminar de **chatflow-agent v0.4.0rc1**, con importantes actualizaciones de concurrencia y arquitectura.

Creado y liderado por **Gustavo Baranda** junto a una comunidad internacional de código abierto, `chatflow-agent` está diseñado para eliminar la sobrecarga innecesaria de dependencias y el bloqueo con proveedores específicos, proporcionando concurrencia de nivel empresarial, memoria resiliente y conectividad multicanal.

---

## Aspectos Destacados de la Arquitectura

<Cards>
  <Card title="Sin Bloqueo de SDKs">
    Conéctate a los LLMs mediante HTTP REST asíncrono y puro utilizando `httpx`. No se requieren SDKs monolíticos de proveedores ni dependencias pesadas en tiempo de ejecución.
  </Card>
  <Card title="Handoffs Multi-Agente Nativos">
    Declara enjambres colaborativos. Los agentes delegan tareas dinámicamente mediante herramientas `transfer_to_*` sintetizadas, con las transferencias por turno limitadas por `max_handoffs_per_turn`.
  </Card>
  <Card title="Memoria Transaccional Resiliente">
    Cada turno crea un punto de control del historial, el agente activo y los metadatos. Si el turno falla, se cancela o alcanza su `turn_timeout`, se restauran. Las operaciones de SQLite respaldado en archivo se ejecutan en un grupo dedicado de hilos de trabajo.
  </Card>
  <Card title="Preparado para Múltiples Canales">
    Despliega tus agentes sin problemas en REPLs de terminal, bots de Telegram o la API Cloud de WhatsApp Business con verificación criptográfica HMAC SHA-256.
  </Card>
</Cards>
