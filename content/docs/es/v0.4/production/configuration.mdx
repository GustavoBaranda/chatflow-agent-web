Los sistemas de IA en producción demandan una estricta separación entre código y configuración. Siguiendo la metodología de [Doce Factores (Twelve-Factor App)](https://12factor.net/config), las credenciales, direcciones de red y umbrales de ejecución deben transmitirse mediante variables de entorno en lugar de codificarse directamente en módulos de Python.

`chatflow-agent` soporta una jerarquía de configuración estructurada: los argumentos explícitos en el constructor tienen prioridad sobre las variables de entorno, las cuales a su vez tienen prioridad sobre los valores por defecto del framework.

## Jerarquía de Resolución de Configuración

Cuando un agente o motor se inicializa, los valores se resuelven en el siguiente orden de prioridad:

```text
Prioridad 1: Argumentos Explícitos del Constructor
    └── Agent(engine=OpenAIEngine(api_key="...", timeout=30.0))
          │ (Sobrescribe todo)
          ▼
Prioridad 2: Variables de Entorno Específicas del Proveedor
    └── OPENAI_API_KEY, GROQ_API_KEY, GEMINI_API_KEY, ANTHROPIC_API_KEY
          │ (Cargadas desde os.environ)
          ▼
Prioridad 3: Preajustes y Valores por Defecto del Framework
    └── URLs base (https://api.openai.com/v1), modelos por defecto, timeout de petición
        (60.0s para OpenAIEngine y AnthropicEngine, 30.0s para GeminiEngine)
```

## Referencia de Variables de Entorno

El propio SDK solo lee las variables de proveedores que se indican a continuación. Las variables de canales de la segunda tabla son una convención de nombres para el código de tu aplicación (tú mismo pasas los valores a los constructores de los canales); el SDK no las lee.

### Credenciales de Proveedores de LLM

| Variable | Proveedor Destino | Descripción | Valor por Defecto de Respaldo |
| :--- | :--- | :--- | :--- |
| `OPENAI_API_KEY` | OpenAI | Token Bearer para endpoints oficiales de OpenAI. | `None` (Requerido para OpenAI) |
| `GROQ_API_KEY` | Groq Cloud | Token Bearer para LPUs de Groq (`provider="groq"`). | `None` (Requerido para Groq) |
| `DEEPSEEK_API_KEY` | DeepSeek | Token Bearer para API de DeepSeek (`provider="deepseek"`). | `None` (Requerido para DeepSeek) |
| `XAI_API_KEY` | xAI Grok | Token Bearer para endpoints de xAI Grok (`provider="grok"`). | `None` (Requerido para Grok) |
| `GEMINI_API_KEY` | Google Gemini | Clave de API para los endpoints REST de la Gemini Developer API (Google AI Studio). Vertex AI y las Application Default Credentials no están soportadas en v0.4.0rc1. | `GOOGLE_API_KEY` |
| `GOOGLE_API_KEY` | Google Gemini | Clave alternativa de respaldo para entornos de Google Cloud. | `None` |
| `GOOGLE_GEMINI_BASE_URL` | Google Gemini | Anulación de URL base para proxies de Gemini. | `https://generativelanguage.googleapis.com` |
| `ANTHROPIC_API_KEY` | Anthropic | Clave de API para Messages API de Claude (`x-api-key`). | `None` (Requerido para Anthropic) |
| `OLLAMA_API_KEY` | Ollama | Token opcional para pasarelas autenticadas de Ollama. | `"ollama"` (Clave ficticia segura) |
| `{PROVIDER}_BASE_URL` | Preajustes compatibles con OpenAI | Anulación de la URL base que `OpenAIEngine` lee para su proveedor, p. ej. `OPENAI_BASE_URL`, `GROQ_BASE_URL`, `OLLAMA_BASE_URL`. Una URL remota no oficial requiere entonces un `api_key` explícito. | URL oficial del preajuste |

### Credenciales de Canales de Integración

| Variable | Integración | Descripción |
| :--- | :--- | :--- |
| `TELEGRAM_BOT_TOKEN` | Telegram | Token de API HTTP emitido por @BotFather. |
| `WHATSAPP_VERIFY_TOKEN` | WhatsApp | Token de verificación para el desafío de suscripción de webhook de Meta. |
| `WHATSAPP_ACCESS_TOKEN` | WhatsApp | Token de acceso de System User con permiso `whatsapp_business_messaging`. |
| `WHATSAPP_PHONE_NUMBER_ID` | WhatsApp | Identificador del número de teléfono en la consola de Meta Developer. |
| `WHATSAPP_APP_SECRET` | WhatsApp | Secreto de la aplicación de Meta utilizado para verificar la firma HMAC SHA-256 de las cargas útiles (el nombre que sugiere el mensaje de error del SDK). |

## Ejemplo de Configuración en Producción

El enfoque recomendado en producción es definir una clase de configuración tipada (ej. usando `pydantic-settings` o `dataclasses`) para validar todas las variables al iniciar la aplicación:

```python
import os
from dataclasses import dataclass
from chatflow_agent import Agent, Runner
from chatflow_agent.core.memory import SQLiteSessionStore
from chatflow_agent.core.engines.openai_compatible import OpenAIEngine

@dataclass(frozen=True)
class AppConfig:
    """Validated application configuration."""
    database_path: str = os.getenv("CHATFLOW_DB_PATH", "production_sessions.db")
    max_tool_iterations: int = int(os.getenv("CHATFLOW_MAX_ITERATIONS", "8"))
    max_handoffs: int = int(os.getenv("CHATFLOW_MAX_HANDOFFS", "4"))
    llm_timeout: float = float(os.getenv("CHATFLOW_LLM_TIMEOUT", "45.0"))
    environment: str = os.getenv("ENVIRONMENT", "production")

config = AppConfig()

# Configurar motor con tiempo de espera explícito para producción
production_engine = OpenAIEngine(
    api_key=os.environ.get("OPENAI_API_KEY"),
    provider="openai",
    timeout=config.llm_timeout,
)

# Configurar almacenamiento SQLite persistente
store = SQLiteSessionStore(
    db_path=config.database_path,
    default_max_turns=30,
)

support_agent = Agent(
    name="CustomerSupport",
    model="gpt-4o",
    engine=production_engine,
    instructions="Provide timely and professional customer service.",
)

runner = Runner(
    starting_agent=support_agent,
    session_store=store,
    max_tool_iterations=config.max_tool_iterations,
    max_handoffs_per_turn=config.max_handoffs,
)
```

## Manejo de Credenciales Sensibles en CI/CD

<Callout type="warn" title="Cero Filtración de Credenciales">
Nunca confirmes archivos `.env`, tokens de API ni secretos en repositorios Git. Agrega siempre `.env`, `.env.*` y `*.db` a tu `.gitignore`.
</Callout>

### Entradas Recomendadas para `.gitignore`

```bash
# Entorno y Secretos
.env
.env.local
.env.production
*.pem
*.key

# Bases de Datos Persistentes de Sesión
*.db
*.sqlite
*.sqlite3

# Bytecode y Caché de Python
__pycache__/
*.pyc
.venv/
```

### Plantilla de Archivo de Entorno (`.env.example`)

Proporciona una plantilla limpia en tu repositorio para la incorporación de miembros del equipo:

```bash
# Proveedores de LLM
OPENAI_API_KEY="your-openai-api-key"
GROQ_API_KEY="your-groq-api-key"
GEMINI_API_KEY="your-gemini-api-key"
ANTHROPIC_API_KEY="your-anthropic-api-key"

# Ajustes de Aplicación
ENVIRONMENT="development"
CHATFLOW_DB_PATH="sessions.db"
CHATFLOW_LLM_TIMEOUT="45.0"
CHATFLOW_MAX_ITERATIONS="10"
CHATFLOW_MAX_HANDOFFS="5"
```
