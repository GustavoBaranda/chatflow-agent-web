Operar enjambres multi-agente en producción requiere visibilidad integral. Cuando un agente transfiere una conversación, invoca APIs externas o activa respuestas de respaldo, los operadores necesitan registros estructurados e identificadores de correlación para diagnosticar latencias, investigar anomalías y auditar decisiones.

`chatflow-agent` v0.4.0rc1 utiliza loggers de la biblioteca estándar de Python para el runner, las herramientas, los almacenes de sesiones, los motores de proveedores y las integraciones de canales. Las aplicaciones pueden asociar su propio formateador estructurado.

## Jerarquía de Loggers

Todos los loggers se organizan bajo el espacio de nombres `chatflow_agent`. Puedes configurar la verbosidad globalmente o ajustar componentes individuales:

```text
chatflow_agent
├── chatflow_agent.runner      (Fallos de ejecución de herramientas con trace_id; reversiones fallidas)
├── chatflow_agent.tools       (Advertencias de esquemas de herramientas, p. ej. anotaciones no resueltas)
├── chatflow_agent.memory      (Sesión eliminada o modificada durante un turno)
├── chatflow_agent.engine
│   ├── chatflow_agent.engine.openai     (Advertencias de reintento: estado HTTP y errores de conexión)
│   ├── chatflow_agent.engine.gemini     (Advertencias de reintento de peticiones REST; clave de API ocultada)
│   └── chatflow_agent.engine.anthropic  (Advertencias de reintento: estado HTTP y errores de conexión)
├── chatflow_agent.telegram    (Inicio del sondeo, errores de permiso de /reset, errores de mensajes)
└── chatflow_agent.whatsapp    (Rechazos de firma, duplicados, tiempos límite, entrega saliente)
```

El SDK no emite métricas ni trazas, y los loggers de los motores no registran cargas útiles de las peticiones, latencias ni recuentos de tokens. Añade esa instrumentación en tu aplicación si la necesitas.

## Configuración de Registros Estructurados

En producción, formatea los registros como líneas individuales JSON para que los sistemas de ingesta centralizados (como Datadog, CloudWatch o Google Cloud Logging) indexen los campos automáticamente:

```python
import json
import logging
import sys
from chatflow_agent import Agent, Runner

class JSONLogFormatter(logging.Formatter):
    """Format log records as structured JSON."""
    def format(self, record: logging.LogRecord) -> str:
        log_entry = {
            "timestamp": self.formatTime(record, self.datefmt),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
            "module": record.module,
            "lineno": record.lineno,
        }
        if record.exc_info:
            log_entry["exception"] = self.formatException(record.exc_info)
        return json.dumps(log_entry)

def setup_production_logging(log_level: int = logging.INFO) -> None:
    """Initialize structured JSON logging for chatflow-agent."""
    handler = logging.StreamHandler(sys.stdout)
    handler.setFormatter(JSONLogFormatter())
    
    # Configurar logger raíz
    root_logger = logging.getLogger("chatflow_agent")
    root_logger.setLevel(log_level)
    root_logger.handlers = [handler]
    root_logger.propagate = False

if __name__ == "__main__":
    setup_production_logging()
    
    agent = Agent(name="ObservabilityBot", instructions="Test logging.")
    runner = Runner(starting_agent=agent)
    print("Structured logging configured.")
```

## Correlación de Trazas con `trace_id`

Cuando una herramienta falla durante la ejecución, `Runner` genera automáticamente un `trace_id` aleatorio en formato UUID y lo adjunta tanto al registro interno como al mensaje entregado al agente:

```text
[ERROR] 2026-10-30T18:22:15Z chatflow_agent.runner: Tool execution failed [trace_id: 3c9b7e41-0f2d-4e92-bc12-f71e549d8802] - Tool: 'query_database' on agent 'BillingAgent': Error executing tool 'query_database': Connection timed out to db.internal.corp:5432
```

El registro se emite con `exc_info=True`, por lo que tu manejador también recibe el stack trace.

### Por Qué Importa la Correlación

1. **Privacidad del Usuario:** El modelo, y por tanto el usuario final, recibe únicamente el mensaje genérico con el `trace_id`, no el texto de la excepción ni direcciones internas.
2. **Triaje Determinista:** Cuando un cliente reporta *"Mi consulta falló a las 18:22"*, los ingenieros de soporte pueden buscar directamente `trace_id: 3c9b7e41...` en los registros para inspeccionar la excepción y su stack trace. Los argumentos de la herramienta no se registran.

## Inspección de Telemetría de Respuesta

Cada invocación de `Runner.run()` o `Runner.run_async()` devuelve un objeto `AgentResponse` que contiene metadatos de ejecución:

```python
from chatflow_agent import Agent, Runner

agent = Agent(name="Inspector", instructions="Provide analytical responses.")
runner = Runner(starting_agent=agent)

response = runner.run(
    session_id="session-user-99",
    user_message="Calculate quarterly forecast.",
)

# 1. Texto entregado al usuario
print(f"Content: {response.content}")

# 2. Agente activo final que generó la respuesta
print(f"Active Agent: {response.active_agent_name}")

# 3. Lista de nombres de herramientas ejecutadas durante este turno
print(f"Tools Executed: {response.tool_calls_executed}")

# 4. Detalles de transferencia si ocurrió una delegación
if response.handoff:
    print(f"Transferred to: {response.handoff.target_agent_name}")
    print(f"Reason: {response.handoff.reason}")
```

## Inspección de Auditoría del Historial de Conversación

Para auditar los turnos de conversación almacenados en una sesión, recupera el contexto directamente desde el almacén configurado:

```python
from chatflow_agent import Agent, Runner
from chatflow_agent.core.memory import SessionStore

store = SessionStore()
agent = Agent(name="Support", instructions="Help customers.")
runner = Runner(starting_agent=agent, session_store=store)

# Ejecutar turno
runner.run(session_id="sess-42", user_message="Hello, I need assistance.")

# Inspeccionar sesión almacenada
session = store.get(session_id="sess-42")
if session:
    print(f"Total Messages: {len(session.history)}")
    for msg in session.history:
        print(f"[{msg.role.value}] {msg.content}")
```

<Callout type="warn" title="Datos Sensibles en los Logs">
<code>chatflow-agent</code> no instala ningún filtro de logs. Sus motores no registran los encabezados de las peticiones, <code>GeminiEngine</code> elimina su clave de API de los mensajes de error y de los logs, y <code>WhatsAppChannel</code> enmascara los números de teléfono en sus propios mensajes. Otros contenidos aún pueden llegar a tus logs: mensajes de excepción de las herramientas, cuerpos de error del proveedor incluidos en <code>ProviderError</code> (de tamaño acotado) y respuestas de error de Meta. El registro de logs por sí solo no hace que un despliegue cumpla con SOC 2, RGPD u otros marcos similares; añade filtros de ocultación y políticas de retención acordes a tus requisitos.
</Callout>
