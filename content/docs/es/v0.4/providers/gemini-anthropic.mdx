Google Gemini y Anthropic Claude representan dos de las familias de modelos de frontera más capacitadas para flujos de trabajo agénticos. `chatflow-agent` proporciona motores nativos dedicados para ambos proveedores, optimizados para baja latencia, cero dependencias cautivas de SDK y llamadas a herramientas confiables.

---

## Motor Google Gemini

`GeminiEngine` se comunica directamente con la API para desarrolladores de Gemini de Google (`v1beta`) para ejecutar conversaciones multiturno y llamadas a herramientas (function calling).

<Callout type="info" title="Modalidad de API de Gemini Soportada">
`GeminiEngine` soporta la **Gemini Developer API** (claves de API de Google AI Studio). Google Cloud Vertex AI no está soportado por este motor.
</Callout>

### Autenticación y Credenciales

El motor lee las credenciales de las siguientes fuentes, en orden de prioridad:
1. `api_key` pasada directamente a `GeminiEngine(api_key="...")` o `Agent(api_key="...")`.
2. Variable de entorno `GEMINI_API_KEY`.
3. Variable de entorno `GOOGLE_API_KEY`.

Por defecto, la clave de API se transmite a través del encabezado HTTP seguro `x-goog-api-key`. Pasar `api_key_in_query=True` transmite la clave como un parámetro de consulta `?key=` en su lugar:

```python
import os
from chatflow_agent import Agent, Runner
from chatflow_agent.core.engines.gemini import GeminiEngine

# Recomendado: Autenticación segura mediante encabezado
gemini_engine = GeminiEngine(
    api_key=os.environ.get("GEMINI_API_KEY"),
    timeout_seconds=30.0,
    max_retries=3,
)

assistant = Agent(
    name="GeminiAssistant",
    model="gemini-2.5-flash",
    engine=gemini_engine,
    instructions="Provide concise, accurate answers.",
)
```

### Pool de Conexiones y Arquitectura sin Dependencias Cautivas

<div className="flex gap-2 my-3">
  <VersionBadge version="0.4.0rc1" status="prerelease" />
  <VersionBadge version="0.3.4" status="stable" />
</div>

La implementación de Gemini experimentó una transformación arquitectónica fundamental entre versiones:

* **En `v0.3.4` (Estable):** El motor importaba el SDK oficial `google-genai` de Google (`from google import genai`), requiriendo la instalación de librerías cliente externas.
* **En `v0.4.0rc1` (Pre-lanzamiento):** El motor se reescribió por completo utilizando `httpx` asíncrono nativo directamente contra `https://generativelanguage.googleapis.com/v1beta`. Esto elimina dependencias pesadas y habilita un **pool de conexiones persistentes (keepalive)** entre turnos del agente:

```python
# [min-version: 0.4.0rc1]
# [no-exec: requires real gemini api key]
import asyncio
from chatflow_agent import Agent, Runner

agent = Agent(name="Assistant", model="gemini-2.5-flash")
runner = Runner(starting_agent=agent)

async def main():
    # 'async with runner:' mantiene vivas las conexiones HTTP entre turnos
    async with runner:
        res1 = await runner.run_async("session-1", "What is quantum computing?")
        res2 = await runner.run_async("session-1", "Summarize in 3 bullet points.")
        print(res2.text)

asyncio.run(main())
```

### Configuración de Proxies Personalizados

Para enrutar peticiones de Gemini a través de un proxy empresarial o una pasarela de seguridad, define la variable de entorno `GOOGLE_GEMINI_BASE_URL`:

```bash
export GOOGLE_GEMINI_BASE_URL="https://gemini-proxy.internal.corp"
```
El motor añade automáticamente `/v1beta` a la URL base.

## Motor Anthropic Claude

`AnthropicEngine` proporciona integración nativa con Claude 3.5 Sonnet, Claude 3.5 Haiku y Claude 3 Opus de Anthropic a través de la Messages API.

### Autenticación y Encabezados

Las peticiones de Anthropic requieren el encabezado `x-api-key` y el encabezado `anthropic-version` (por defecto `"2023-06-01"`).

El motor lee las credenciales desde:
1. `api_key` pasada explícitamente a `AnthropicEngine(api_key="...")` o `Agent(api_key="...")`.
2. Variable de entorno `ANTHROPIC_API_KEY`.

<Callout type="warn" title="Regla de Seguridad de Credenciales">
Al igual que `OpenAIEngine`, `AnthropicEngine` solo envía `ANTHROPIC_API_KEY` al endpoint oficial `https://api.anthropic.com/v1`. Si especificas una `base_url` personalizada, debes pasar `api_key` de forma explícita.
</Callout>

```python
import os
from chatflow_agent import Agent
from chatflow_agent.core.engines.anthropic import AnthropicEngine

claude_engine = AnthropicEngine(
    api_key=os.environ.get("ANTHROPIC_API_KEY"),
    timeout=60.0,
)

editor = Agent(
    name="Editor",
    model="claude-3-5-sonnet-20241022",
    engine=claude_engine,
    instructions="Edit and refine technical documentation.",
)
```

### Reintentos Automáticos y Retroceso con Jitter

`AnthropicEngine` gestiona automáticamente la limitación de tasa (`429 Too Many Requests`) y errores temporales de pasarela (`500`, `502`, `503`, `504`) mediante un retroceso exponencial (*exponential backoff*):
* **Reintentos Máximos:** 3 intentos.
* **Demora Base:** 1.0 segundo.
* **Demora Máxima:** 10.0 segundos.

Si una respuesta `429` incluye un encabezado `Retry-After`, el motor respeta con precisión el tiempo de espera solicitado por el proveedor antes de reintentar.

## Colaboración Agéntica Multi-Modelo

Una ventaja central de `chatflow-agent` es la capacidad de componer enjambres donde diferentes agentes utilizan distintos modelos fundacionales según sus puntos fuertes:

```python
from chatflow_agent import Agent, Runner
from chatflow_agent.core.engines.gemini import GeminiEngine
from chatflow_agent.core.engines.anthropic import AnthropicEngine

gemini = GeminiEngine()
claude = AnthropicEngine()

researcher = Agent(
    name="Researcher",
    model="gemini-2.5-flash",
    engine=gemini,
    instructions="Gather facts quickly using Gemini's high-throughput processing.",
)

synthesizer = Agent(
    name="Synthesizer",
    model="claude-3-5-sonnet-20241022",
    engine=claude,
    instructions="Synthesize gathered facts into clear, well-structured prose.",
)

# Conectar agentes mediante transferencias (handoffs)
researcher.add_handoff(synthesizer)
synthesizer.add_handoff(researcher)

runner = Runner(starting_agent=researcher)
```

En este enjambre:
1. El **Researcher** opera con Gemini 2.5 Flash para un procesamiento y búsqueda masiva a alta velocidad.
2. Una vez recopilados los datos, la sesión se transfiere al **Synthesizer** ejecutándose en Claude 3.5 Sonnet.
3. El historial de mensajes y los IDs de llamadas a herramientas se normalizan automáticamente, evitando cualquier incompatibilidad de formato entre proveedores.
