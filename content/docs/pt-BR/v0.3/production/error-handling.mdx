Construir sistemas multiagente resilientes exige tolerância a falhas estruturada. Indisponibilidades de provedores de LLM, timeouts de rede, argumentos inválidos de ferramentas e exceções imprevistas devem ser tratados adequadamente sem corromper o estado da conversa.

O `chatflow-agent` implementa um modelo de recuperação em camadas: erros de ferramentas são informados ao LLM como um resultado de erro genérico para que o turno possa continuar, enquanto uma exceção comum que escapa do turno trunca o histórico da conversa até o tamanho anterior ao turno (a v0.3.4 não restaura o agente ativo nem os metadados, e não reverte turnos cancelados).

## Hierarquia de Exceções do SDK

Todas as exceções no `chatflow-agent` herdam de `ChatFlowError`. Isso permite que a sua aplicação diferencie erros do framework de exceções padrão do Python.

```text
ChatFlowError (Base)
├── DependencyError (Dependências opcionais ausentes de canais)
├── ToolExecutionError (Erro não capturado durante a execução de ferramenta)
├── ToolSchemaError (Anotação de união com um membro não mapeável) [v0.4.0rc1]
├── AgentHandoffError (Destino de handoff desconhecido)
├── ProviderError (Erro de status de API de LLM, falha de rede ou timeout)
├── ReentrantTurnError (Turno aninhado da mesma sessão iniciado por um turno ativo) [v0.4.0rc1]
└── SessionDeletedError (Mensagem despachada para uma sessão excluída) [v0.4.0rc1]
```

### Tabela de Referência de Exceções

| Classe de Exceção | Herda de | Lançada Quando | Estratégia de Recuperação |
| :--- | :--- | :--- | :--- |
| `ChatFlowError` | `Exception` | Classe base para todas as exceções do SDK. | Tratar nos pontos de entrada das requisições. |
| `DependencyError` | `ChatFlowError` | Um extra opcional de canal (ex.: `[telegram]`, `[whatsapp]`) não está instalado. | Instalar o extra necessário com `pip install "chatflow-agent[extra]"`. |
| `ToolExecutionError` | `ChatFlowError` | Uma função de ferramenta lança uma exceção não tratada durante a execução. | Dentro de um turno, o `Runner` a registra nos logs e retorna ao modelo um `ToolResult(is_error=True)` genérico. |
| `ToolSchemaError` <VersionBadge version="0.4.0rc1" status="prerelease" /> | `ChatFlowError` | Uma ferramenta é criada com uma anotação de união que contém um membro sem mapeamento de esquema. Parâmetros sem anotação são permitidos. | Corrigir assinaturas de tipo da função em tempo de desenvolvimento. |
| `AgentHandoffError` | `ChatFlowError` | O agente de destino do handoff não existe no registro do `Runner`. Exceder `max_handoffs_per_turn` não levanta exceção: em vez disso, adiciona um resultado de erro de ferramenta. | Verificar destinos de handoff. |
| `ProviderError` | `ChatFlowError` | O provedor upstream do modelo retorna um código de erro HTTP (ex.: 429, 500, 503). | Implementar retentativas com backoff exponencial ou fallback para outro motor. |
| `ReentrantTurnError` <VersionBadge version="0.4.0rc1" status="prerelease" /> | `ChatFlowError`, `RuntimeError` | Código executando dentro de um turno inicia outro turno na mesma sessão. | Utilizar filas de processamento em segundo plano ou despachantes sequenciais. |
| `SessionDeletedError` <VersionBadge version="0.4.0rc1" status="prerelease" /> | `ChatFlowError` | Uma mensagem é processada para uma sessão expurgada durante a execução. | Recriar a sessão ou orientar o usuário a reiniciar o fluxo. |

## Autocorreção Autônoma de Ferramentas

Quando uma ferramenta registrada lança uma exceção, incluindo um `TypeError` causado por argumentos que a função não aceita, o `Runner` captura a falha e retorna um erro estruturado ao modelo, em vez de interromper o turno. A v0.3.4 não valida os argumentos das ferramentas contra o esquema antes de chamar a função:

```python
import logging
from chatflow_agent import Agent, Runner, tool

logger = logging.getLogger("app.tools")

@tool
def process_refund(order_id: str, amount: float) -> str:
    """Issue a refund for an order.

    Args:
        order_id: Order identifier formatted as ORD-XXXX.
        amount: Positive monetary value to refund.
    """
    if not order_id.startswith("ORD-"):
        raise ValueError("Invalid order format. Order ID must begin with 'ORD-'.")
    if amount <= 0:
        raise ValueError("Refund amount must be strictly greater than 0.")
    return f"Refund of ${amount:.2f} processed for order {order_id}."

agent = Agent(
    name="RefundBot",
    model="gpt-4o",
    provider="openai",
    tools=[process_refund],
    instructions="Process refunds accurately. If an order ID format is invalid, clarify with the user.",
)

runner = Runner(starting_agent=agent)
```

### O Que Acontece Durante a Execução

1. O modelo invoca `process_refund(order_id="12345", amount=50.0)`.
2. `process_refund` lança `ValueError: Invalid order format. Order ID must begin with 'ORD-'.`.
3. O `Runner` atribui um `trace_id` exclusivo (UUID4) e anexa um `ToolResult`:
   ```json
   {
     "tool_call_id": "call_abc123",
     "name": "process_refund",
     "content": "Tool execution failed [trace_id: a8c2...]. Please try a different approach or inform the user.",
     "is_error": true
   }
   ```
4. A exceção original é registrada internamente com o mesmo `trace_id`. O modelo recebe apenas o resultado genérico com `is_error=True` e não consegue inferir o detalhe privado da exceção.

<Callout type="info" title="Proteção Contra Loops de Retentativa">
Para prevenir loops infinitos em que um agente falha repetidamente em chamadas de ferramenta, o `Runner` impõe `max_tool_iterations` (padrão: `10`). Se o limite for atingido sem uma resposta de texto final, o runner retorna uma mensagem de fallback controlada sem travar a aplicação.
</Callout>

## Reversão Transacional de Turnos (Rollback)

Turnos multiagente podem alterar o histórico, trocar o agente ativo e atualizar metadados. A versão estável v0.3.4 oferece uma garantia mais limitada que uma transação completa.

Para exceções comuns capturadas pelo `Runner`, a v0.3.4 apenas trunca `session.history` até o tamanho anterior ao turno:

```text
Início do Turno
    ├── Capturar Ponto de Controle: tamanho de history
    ├── Anexar Mensagem de Entrada do Usuário
    ├── Executar Turnos de LLM e Ferramentas
    │     ├── Sucesso: Confirmar resposta final do assistente no SessionStore
    │     └── Exceção comum: truncar history ao tamanho anterior
    └── Liberar Bloqueio da Sessão
```

### Exemplo de Reversão em Código

```python
import asyncio
from chatflow_agent import Agent, Runner
from chatflow_agent.exceptions import ProviderError

def build_resilient_runner(agent: Agent) -> Runner:
    """Configure a runner with bounded handoffs and tool iterations."""
    return Runner(
        starting_agent=agent,
        max_tool_iterations=6,
        max_handoffs_per_turn=3,
    )

async def execute_turn_with_recovery(
    runner: Runner,
    session_id: str,
    user_message: str,
) -> str:
    """Execute a turn with explicit exception handling and graceful fallback."""
    try:
        response = await runner.run_async(
            session_id=session_id,
            user_message=user_message,
        )
        return response.content
    except ProviderError as err:
        # A v0.3.4 reverte o histórico para esta exceção comum.
        # active_agent e metadata não são restaurados.
        return "Our AI inference service is temporarily degraded. Please retry in a few moments."
    except TimeoutError:
        # Cancelamento externo na v0.3.4 não garante rollback.
        return "The request took too long to complete. Please try a simpler question."
    except Exception as err:
        return "An unexpected system error occurred. Our operations team has been notified."
```

## Tempos Limite de Turno e Fronteiras de Recursos

A versão estável v0.3.4 não possui o parâmetro `turn_timeout`. Envolver `run_async` com `asyncio.wait_for` cancela a tarefa, mas `CancelledError` não é coberto por `except Exception`; portanto, o rollback do histórico não é garantido. Prefira timeouts do provedor ou canal; se a aplicação cancelar externamente, trate a sessão como potencialmente parcial e recupere-a de forma explícita.

```python
# [no-exec: illustrative turn timeout call]
import asyncio
from chatflow_agent import Runner

async def run_with_external_timeout(runner: Runner):
    try:
        return await asyncio.wait_for(
            runner.run_async(
                session_id="customer-1029",
                user_message="Analyze this quarterly financial audit report...",
            ),
            timeout=45.0,
        )
    except asyncio.TimeoutError:
        # v0.3.4: recupere ou descarte esta sessão antes de reutilizá-la.
        raise
```

<Callout type="info" title="Timeout transacional na prévia">
<VersionBadge version="0.4.0rc1" status="prerelease" /> introduz o parâmetro explícito `turn_timeout` e restaura histórico, agente ativo e metadados quando ele expira. Essa garantia não se aplica à versão estável v0.3.4.
</Callout>

## Lista de Verificação de Melhores Práticas

- **Trate `ChatFlowError`:** Intercepte exceções do framework antes de permitir que propaguem para os endpoints HTTP.
- **Defina Limites de Iterações:** Nunca configure `max_tool_iterations` ou `max_handoffs_per_turn` com valores ilimitados.
- **Retorne Erros Descritivos nas Ferramentas:** O modelo nunca vê o texto de uma exceção lançada por uma ferramenta, apenas um erro genérico com um `trace_id`. Se o modelo deve reagir a um problema específico (por exemplo, um ID de pedido malformado), faça a ferramenta **retornar** uma mensagem de erro curta e segura para o usuário, em vez de lançar uma exceção.
- **Registre IDs de Rastreamento:** Capture o `trace_id` gerado nos logs do `Runner` para correlacionar chamados de suporte com traces internos do sistema.
