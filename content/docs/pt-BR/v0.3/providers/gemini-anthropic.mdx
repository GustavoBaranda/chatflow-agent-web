O Google Gemini e o Anthropic Claude representam duas famílias de modelos avançadas para fluxos de trabalho agentivos. O `chatflow-agent` v0.3.4 disponibiliza motores dedicados para ambos os provedores e usa seus clientes para oferecer conversas de múltiplos turnos e chamadas de ferramentas.

---

## Motor Google Gemini

Na versão estável v0.3.4, o `GeminiEngine` usa o cliente `google-genai` do Google para se comunicar com a Gemini Developer API e executar conversas de múltiplos turnos e chamadas de funções.

<Callout type="info" title="Variante Suportada da API Gemini">
O `GeminiEngine` suporta a **Gemini Developer API** (chaves de API do Google AI Studio). O Google Cloud Vertex AI não é suportado diretamente por este motor.
</Callout>

### Autenticação e Credenciais

Na versão estável v0.3.4, o motor lê as credenciais das seguintes fontes, por ordem de prioridade:
1. `api_key` passada diretamente para `GeminiEngine(api_key="...")` ou `Agent(api_key="...")`.
2. Variável de ambiente `GEMINI_API_KEY`.

<Callout type="info" title="Opções de credenciais na prévia">
<VersionBadge version="0.4.0rc1" status="prerelease" /> adiciona o fallback `GOOGLE_API_KEY` e a opção `api_key_in_query`. Essas opções não estão disponíveis na versão estável v0.3.4.
</Callout>

```python
import os
from chatflow_agent import Agent, Runner
from chatflow_agent.core.engines.gemini import GeminiEngine

# v0.3.4: a chave é repassada ao cliente google-genai
gemini_engine = GeminiEngine(
    api_key=os.environ.get("GEMINI_API_KEY"),
    timeout_seconds=30.0,
    max_retries=3,
)

assistant = Agent(
    name="GeminiAssistant",
    model="gemini-2.5-flash",
    engine=gemini_engine,
    instructions="Provide concise, accurate answers.",
)
```

### Arquitetura do Motor Gemini por Versão

<div className="flex gap-2 my-3">
  <VersionBadge version="0.3.4" status="stable" />
  <VersionBadge version="0.4.0rc1" status="prerelease" />
</div>

A implementação do Gemini passou por uma evolução arquitetural fundamental entre as versões:

* **Na versão `v0.3.4` (Estável):** O motor usa o SDK oficial `google-genai` do Google (`from google import genai`), que é instalado automaticamente como dependência principal. Não há pool de conexões.
* **Na versão `v0.4.0rc1` (Pré-lançamento):** O motor foi reescrito utilizando `httpx` assíncrono nativo contra `https://generativelanguage.googleapis.com/v1beta`. Isso remove a dependência `google-genai` e, dentro de um escopo `async with runner:`, permite que as requisições ao Gemini compartilhem um único cliente HTTP com pool de conexões.

Na v0.3.4, execute os turnos diretamente em um runner compartilhado:

```python
# [no-exec: requires real gemini api key]
import asyncio
from chatflow_agent import Agent, Runner

agent = Agent(
    name="Assistant",
    instructions="Provide concise, accurate answers.",
    model="gemini-2.5-flash",
)
runner = Runner(starting_agent=agent)

async def main():
    # Na v0.3.x, execute turnos assíncronos diretamente no runner
    res1 = await runner.run_async("session-1", "What is quantum computing?")
    res2 = await runner.run_async("session-1", "Summarize in 3 bullet points.")
    print(res2.content)

asyncio.run(main())
```

### Configuração de Proxy Customizado (Pré-lançamento)

<VersionBadge version="0.4.0rc1" status="prerelease" /> Para direcionar requisições do Gemini por um proxy corporativo na prévia, defina `GOOGLE_GEMINI_BASE_URL`. A versão estável v0.3.4 não oferece suporte a essa variável:

```bash
export GOOGLE_GEMINI_BASE_URL="https://gemini-proxy.internal.corp"
```
O motor v0.4.0rc1 anexa automaticamente `/v1beta` à URL base.

## Motor Anthropic Claude

O `AnthropicEngine` fornece integração nativa com os modelos Claude 3.5 Sonnet, Claude 3.5 Haiku e Claude 3 Opus da Anthropic através da Messages API.

### Autenticação e Cabeçalhos

Requisições para a Anthropic exigem o cabeçalho `x-api-key` e o cabeçalho `anthropic-version` (padrão `"2023-06-01"`).

O motor obtém credenciais a partir de:
1. `api_key` passada explicitamente para `AnthropicEngine(api_key="...")` ou `Agent(api_key="...")`.
2. Variável de ambiente `ANTHROPIC_API_KEY`.

<Callout type="warn" title="Regra de Segurança de Credenciais">
Assim como o `OpenAIEngine`, o `AnthropicEngine` envia `ANTHROPIC_API_KEY` exclusivamente para o endpoint oficial `https://api.anthropic.com/v1`. Se você especificar um `base_url` customizado, deve passar a `api_key` explicitamente.
</Callout>

```python
import os
from chatflow_agent import Agent
from chatflow_agent.core.engines.anthropic import AnthropicEngine

claude_engine = AnthropicEngine(
    api_key=os.environ.get("ANTHROPIC_API_KEY"),
    timeout=60.0,
)

editor = Agent(
    name="Editor",
    model="claude-3-5-sonnet-20241022",
    engine=claude_engine,
    instructions="Edit and refine technical documentation.",
)
```

### Tentativas Automáticas com Backoff Exponencial

O `AnthropicEngine` repete automaticamente requisições em caso de limite de taxa (`429 Too Many Requests`), erros transitórios de servidor (`500`, `502`, `503`, `504`), o status de sobrecarga da Anthropic (`529`) e erros de conexão, usando recuo exponencial (*exponential backoff*) com jitter:
* **Tentativas Máximas:** 3 novas tentativas após a primeira (até 4 requisições).
* **Atraso Base:** 1.0 segundo.
* **Atraso Máximo:** 10.0 segundos.

Esses valores são fixos na v0.3.4; não são parâmetros do construtor. Quando uma resposta repetida inclui um cabeçalho `Retry-After` numérico, esse valor substitui o atraso exponencial, mas a espera continua limitada a 10 segundos, portanto um atraso solicitado maior não é totalmente respeitado.

## Colaboração entre Agentes com Múltiplos Modelos

Uma das grandes vantagens do `chatflow-agent` é construir enxames onde diferentes agentes empregam modelos de fundação distintos de acordo com seus pontos fortes:

```python
from chatflow_agent import Agent, Runner
from chatflow_agent.core.engines.gemini import GeminiEngine
from chatflow_agent.core.engines.anthropic import AnthropicEngine

gemini = GeminiEngine()
claude = AnthropicEngine()

researcher = Agent(
    name="Researcher",
    model="gemini-2.5-flash",
    engine=gemini,
    instructions="Gather facts quickly using Gemini's high-throughput processing.",
)

synthesizer = Agent(
    name="Synthesizer",
    model="claude-3-5-sonnet-20241022",
    engine=claude,
    instructions="Synthesize gathered facts into clear, well-structured prose.",
)

# Conectar agentes via handoffs
researcher.add_handoff(synthesizer)
synthesizer.add_handoff(researcher)

runner = Runner(starting_agent=researcher)
```

Neste enxame:
1. O **Researcher** roda no Gemini 2.5 Flash para ingestão rápida e pesquisa de dados.
2. Com os dados coletados, a sessão transfere o controle para o **Synthesizer** no Claude 3.5 Sonnet.
3. <VersionBadge version="0.4.0rc1" status="prerelease" /> Na prévia, mensagens históricas e IDs de chamadas de ferramentas são normalizados. A versão estável v0.3.4 não oferece essa garantia.
