O `chatflow-agent` é construído em torno de cinco abstrações componíveis. Entender como elas interagem torna simples projetar desde um chatbot com ferramentas até um enxame multi-provedor.

## 1. `Agent` — Persona, Ferramentas e Regras de Roteamento

Um `Agent` (`chatflow_agent.core.agent.Agent`) é um objeto declarativo que representa um especialista de IA. Um agente **não** guarda estado conversacional; ele define:

* **`name`** (`str`): Identificador único dentro de um enxame (ex.: `"TriageAgent"`, `"BillingSpecialist"`). Usado para sintetizar ferramentas de handoff (`transfer_to_billingspecialist`).
* **`instructions`** (`str | Callable[[], str]`): O prompt do sistema — string estática ou função sem argumentos avaliada dinamicamente no início de cada turno.
* **`model`** (`str`): Identificador do modelo (padrão `"gemini-2.5-flash"`).
* **`tools`** (`list[Tool | Callable]`): Funções autorizadas que o agente pode executar, validadas em tempo de execução pelo Pydantic (`validate_args=True` por padrão).
* **`handoffs`** (`list[Agent]`): Agentes destino para os quais este agente pode delegar a conversa.
* **`provider` / `base_url` / `api_key` / `engine`**: Sobrescritas opcionais de roteamento para que cada agente de um enxame use um provedor LLM diferente. Nomes de provedor inválidos ou ausência de credenciais em endpoints remotos customizados falham imediatamente com `ConfigurationError`.

```python
# [executable]
from datetime import datetime, timezone
from chatflow_agent import Agent

def dynamic_prompt() -> str:
    now = datetime.now(timezone.utc).strftime("%Y-%m-%d %H:%M UTC")
    return f"You are a support specialist. Current server time: {now}."

agent = Agent(
    name="SupportSpecialist",
    instructions=dynamic_prompt,
    model="gpt-4o",
)

assert "Current server time:" in agent.get_instructions()
```

## 2. `Runner` — O Orquestrador de Turnos

O `Runner` (`chatflow_agent.core.runner.Runner`) coordena a execução entre sessões, agentes, motores e ferramentas:

1. **Descoberta do Registro de Agentes:** Na inicialização, o `Runner` realiza uma busca em largura (BFS) a partir de `starting_agent` percorrendo `.handoffs` e registrando cada `Agent` alcançável. Se duas instâncias distintas de `Agent` compartilharem o mesmo `.name`, o `Runner` lança `ValueError` imediatamente.
2. **Bloqueio de Concorrência por Sessão:** Chamadas a `run_async()` para o mesmo `session_id` adquirem um `asyncio.Lock` dedicado para impedir corrupção do histórico. Na `v0.4.0`, se uma ferramenta ou task em segundo plano iniciada dentro de um turno tentar chamar `run()` ou `run_async()` para o **mesmo** `session_id`, o `Runner` lança `ReentrantTurnError` imediatamente em vez de entrar em deadlock.
3. **Redefinição Segura de Sessão (`reset_session_async`):** `await runner.reset_session_async(session_id) -> bool` e `runner.reset_session(session_id) -> bool` coordenam a limpeza do histórico com o lock de turno, a barreira de trabalho síncrono e a guarda de reentrância, retornando `True` se uma sessão existente foi limpa e `False` caso contrário.
4. **Loop de Execução Limitado:** Dentro de um turno, o `Runner` aplica `max_tool_iterations` (padrão `10`) e `max_handoffs_per_turn` (padrão `5`) para evitar loops infinitos.
5. **Reversão Transacional de Turno:** Se um motor lançar `ProviderError`, um handoff falhar, ou um turno for cancelado ou exceder `turn_timeout`, o `Runner` restaura o histórico de mensagens, `active_agent` e `metadata` ao estado exato anterior ao turno.

## 3. `BaseEngine` — Inferência LLM Intercambiável

Os motores (`chatflow_agent.core.engines.base.BaseEngine`) implementam um único contrato assíncrono:

```python
async def generate_turn_async(
    self,
    agent: Agent,
    history: list[Message],
) -> EngineTurnResult:
    ...
```

De fábrica, o `chatflow-agent` traz três motores de produção — todos baseados em `httpx.AsyncClient` sem dependências pesadas de SDKs de provedores:

* **`GeminiEngine`**: Comunica-se diretamente com a API REST do Google Gemini (`https://generativelanguage.googleapis.com/v1beta`), com backoff exponencial automático, suporte a `Retry-After`, IDs sintéticos resistentes a colisões (`cf_gemini_<24 hex>`) e redação de chaves API.
* **`OpenAIEngine`**: Suporta OpenAI (`https://api.openai.com/v1`) além de presets integrados para `deepseek`, `groq`, `grok` e `ollama` local, com IDs sintéticos sem estado (`call_<24 hex>`).
* **`AnthropicEngine`**: Conecta-se à API de Mensagens da Anthropic (`/v1/messages`) com tradução nativa de blocos `tool_use` / `tool_result` e `max_tokens: int = 4096` configurável.

## 4. `Tool` e `@tool` — Chamada de Funções Validada

Um `Tool` (`chatflow_agent.core.tools.Tool`) encapsula uma função Python síncrona ou assíncrona:

* Inspeciona anotações de tipo Python (`str`, `int`, `float`, `bool`, `list[T]`, `Sequence[T]`, `set[T]`, `frozenset[T]`, `tuple[T, ...]`, `dict`, `Optional[T]` / `T | None`, uniões de tipos suportados e `Annotated[T, ...]`) para compilar schemas de function-calling. Lança `ToolSchemaError` na definição se uma anotação de união contiver um membro sem mapeamento (ex.: `CustomClass | None`), enquanto tipos não-união não suportados preservam o fallback compatível `STRING` / `string`.
* Valida e coage argumentos fornecidos pelo modelo em tempo de execução antes de chamar a função (`validate_args=True` por padrão), lançando `ToolArgumentValidationError` (subclasse de `ToolExecutionError`) em entradas inválidas.
* Despacha funções síncronas e aguarda corrotinas (`inspect.iscoroutinefunction`).
* Se uma ferramenta lançar uma exceção em tempo de execução, o `Runner` a captura, registra um `trace_id` no log e retorna um `ToolResult` sanitizado (`is_error=True`) ao LLM sem expor stack traces aos usuários finais.

## 5. `BaseSessionStore` e `SessionContext` — Estado e Memória

O estado conversacional é encapsulado em `SessionContext`:

* **`session_id`** (`str`): Chave única de conversa (ex.: telefone do WhatsApp, chat ID do Telegram ou UUID).
* **`history`** (`list[Message]`): Sequência ordenada de mensagens `USER`, `ASSISTANT`, `TOOL` e `SYSTEM`, limitada por janela deslizante (`max_turns`, padrão `50` turnos de usuário) que preserva pares de chamadas de ferramentas e uma âncora `[System Note]`.
* **`active_agent`** (`Agent`): Agente atendendo a sessão atualmente; atualizado e persistido após cada handoff.
* **`metadata`** (`dict[str, Any]`): Dicionário JSON-serializável persistido junto à sessão (com isolamento por cópia profunda em `SessionStore`, serialização ISO-8601 para `datetime`/`date`/`time` e `JsonCodecError` para objetos não serializáveis).

Escolha entre:
* **`SessionStore`**: Armazenamento rápido em memória com isolamento por cópia profunda de metadados e deduplicação thread-safe.
* **`SQLiteSessionStore`**: Armazenamento durável em SQLite com journaling `WAL`, suporte persistente a `:memory:`, leituras em transação única, reversão transacional de turnos e deduplicação de webhooks de 192 horas (`8 dias`).
