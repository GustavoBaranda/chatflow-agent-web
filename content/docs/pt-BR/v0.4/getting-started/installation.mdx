O `chatflow-agent` é distribuído no [PyPI](https://pypi.org/project/chatflow-agent/) com um núcleo enxuto. Na **`v0.4.0`**, o pacote principal depende apenas de **`pydantic>=2.6.0`** e **`httpx>=0.27.0,<1.0`** (`google-genai` foi removido na `v0.4.0` porque o `GeminiEngine` agora chama diretamente a API REST do Gemini sobre `httpx.AsyncClient`). As integrações de canais (`telegram`, `whatsapp`, `webhook`) são empacotadas como extras opcionais para manter os contêineres de produção leves.

## Requisitos do Sistema

* **Python:** `>= 3.10` (`Requires-Python: >=3.10`; testado em Python 3.10, 3.11, 3.12 e 3.13)
* **Gerenciadores de Pacotes:** `pip`, `uv` ou `poetry`
* **Sistemas Operacionais:** A CI do SDK roda em Linux (Ubuntu) e Windows. Por ser Python puro sem marcadores de plataforma, espera-se que funcione em macOS e arm64, embora não façam parte da matriz de CI.
* **Dependências Principais (Instaladas Automaticamente):**
  * `pydantic >= 2.6.0` (Validação de dados, validação de argumentos de ferramentas em tempo de execução e helpers de schema)
  * `httpx >= 0.27.0, < 1.0` (Transporte HTTP assíncrono para OpenAI, Gemini, Anthropic, Ollama e WhatsApp)
  * A persistência SQLite utiliza a biblioteca nativa `sqlite3` do Python sem drivers externos.

## Instalando o Pacote

<Steps>
  <Step>
    ### Crie um Ambiente Virtual Isolado

    Instale sempre o `chatflow-agent` dentro de um ambiente virtual dedicado:

    <Tabs items={['venv (Padrão)', 'uv', 'poetry']}>
      <Tab value="venv (Padrão)">
```bash

# Linux / macOS
source .venv/bin/activate

# Windows (PowerShell)
.venv\Scripts\Activate.ps1
```
      </Tab>
      <Tab value="uv">
```bash
uv venv
source .venv/bin/activate
```
      </Tab>
      <Tab value="poetry">
```bash
poetry add chatflow-agent@0.4.0
```
      </Tab>
    </Tabs>
  </Step>

  <Step>
    ### Instale o `chatflow-agent` v0.4.0

    Escolha o comando de instalação adequado à sua implantação:

    <Tabs items={['Core SDK (0.4.0)', 'Extra Telegram', 'Extra WhatsApp', 'Extra Webhook', 'Todos os Extras']}>
      <Tab value="Core SDK (0.4.0)">
```bash
pip install chatflow-agent==0.4.0
```
      </Tab>
      <Tab value="Extra Telegram">

```
      </Tab>
      <Tab value="Extra WhatsApp">

```
      </Tab>
      <Tab value="Extra Webhook">

## Matriz de Dependências Principais e Extras Opcionais

A tabela abaixo reflete exatamente os metadados (`Requires-Dist` e `Provides-Extra`) publicados na wheel **`chatflow-agent==0.4.0`**:

| Linha / Extra | Comando de Instalação | Pacotes Adicionados | Exigido Por |
| :--- | :--- | :--- | :--- |
| *(Core — sempre instalado)* | `pip install chatflow-agent==0.4.0` | `pydantic>=2.6.0`, `httpx>=0.27.0,<1.0` | `Agent`, `Runner`, `OpenAIEngine`, `GeminiEngine`, `AnthropicEngine`, `SessionStore`, `SQLiteSessionStore`, `CLIChannel` |
| `telegram` | `pip install "chatflow-agent[telegram]==0.4.0"` | `python-telegram-bot>=21.0` | `TelegramChannel` |
| `whatsapp` | `pip install "chatflow-agent[whatsapp]==0.4.0"` | `fastapi>=0.110.0`, `uvicorn>=0.29.0` | `WhatsAppChannel` |
| `webhook` | `pip install "chatflow-agent[webhook]==0.4.0"` | `fastapi>=0.110.0`, `uvicorn>=0.29.0` | Endpoints HTTP FastAPI personalizados (não existe canal genérico embutido; consulte [Webhooks e Canais Customizados](/pt-BR/docs/v0.4/integrations/webhook)) |
| `all` | `pip install "chatflow-agent[all]==0.4.0"` | `python-telegram-bot>=21.0`, `fastapi>=0.110.0`, `uvicorn>=0.29.0` | Implantações multicanal completas |
| `dev` | `pip install "chatflow-agent[dev]==0.4.0"` | `pytest>=8.0.0`, `pytest-asyncio>=0.23.0`, `ruff>=0.4.0`, `mypy>=1.9.0` | Contribuir e executar a suíte de testes do SDK |

<Callout type="info" title="Importações Preguiçosas de Canais e DependencyError">
Se você tentar instanciar `TelegramChannel` ou `WhatsAppChannel` sem instalar o extra correspondente, o `chatflow-agent` lança um `DependencyError` descritivo com o comando `pip install` exato necessário.
</Callout>

## Configuração de Chaves de API dos Provedores

O `chatflow-agent` resolve automaticamente as credenciais a partir de variáveis de ambiente padrão quando `api_key` não é passada explicitamente ao construtor do `Agent` ou do motor. Cada provedor lê apenas sua própria variável e somente quando a requisição vai para o endpoint oficial desse provedor (`OPENAI_API_KEY` nunca é enviada a outro provedor ou host remoto customizado):

| Provedor | Variável de Ambiente | Modelo de Exemplo | Classe do Motor |
| :--- | :--- | :--- | :--- |
| **Google Gemini** | `GEMINI_API_KEY` *(usa `GOOGLE_API_KEY` como fallback se ausente; opcional `GOOGLE_GEMINI_BASE_URL` para proxies)* | `gemini-2.5-flash` | `GeminiEngine` |
| **OpenAI** | `OPENAI_API_KEY` | `gpt-4o-mini` | `OpenAIEngine` |
| **Anthropic** | `ANTHROPIC_API_KEY` | `claude-3-5-sonnet-latest` | `AnthropicEngine` |
| **DeepSeek** | `DEEPSEEK_API_KEY` | `deepseek-chat` | `OpenAIEngine(provider="deepseek")` |
| **Groq** | `GROQ_API_KEY` | `llama-3.3-70b-versatile` | `OpenAIEngine(provider="groq")` |
| **xAI Grok** (`provider="grok"` ou `"xai"`) | `XAI_API_KEY` | `grok-2` | `OpenAIEngine(provider="grok")` |
| **Ollama / Gemma (Local)** (`provider="ollama"` ou `"gemma"`) | `OLLAMA_API_KEY` *(opcional; servidores Ollama locais não exigem chave)* | `gemma2:9b` | `OpenAIEngine(provider="ollama")` |

Exporte as variáveis no seu terminal antes de iniciar a aplicação:

<Tabs items={['Linux / macOS (bash/zsh)', 'Windows (PowerShell)']}>
  <Tab value="Linux / macOS (bash/zsh)">
```bash
export OPENAI_API_KEY="sk-..."
export GEMINI_API_KEY="AIza..."
export ANTHROPIC_API_KEY="sk-ant-..."
export XAI_API_KEY="xai-..."
export DEEPSEEK_API_KEY="sk-..."
export GROQ_API_KEY="gsk_..."
```
  </Tab>
  <Tab value="Windows (PowerShell)">
```powershell
$env:OPENAI_API_KEY="sk-..."
$env:GEMINI_API_KEY="AIza..."
$env:ANTHROPIC_API_KEY="sk-ant-..."
$env:XAI_API_KEY="xai-..."
```
  </Tab>
</Tabs>
