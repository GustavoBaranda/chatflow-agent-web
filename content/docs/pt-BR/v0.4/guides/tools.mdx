As ferramentas capacitam os agentes a interagir com ambientes externos, executar computações, consultar bancos de dados e disparar ações de negócio. No **chatflow-agent**, as ferramentas são objetos de primeira classe criados através do decorador `@tool` ou instanciados diretamente com a classe `Tool`.

O framework fornece um motor de introspecção automatizado que traduz anotações de tipo nativas do Python e docstrings em declarações padronizadas de OpenAPI e JSON Schema para modelos Google Gemini, OpenAI e Anthropic sem a necessidade de esquemas manuais.

---

## Definindo Ferramentas com `@tool`

A forma padrão de construir uma ferramenta é através do decorador `@tool`. Você pode aplicá-lo de forma direta ou customizar seu nome e descrição:

### 1. Decorador Simples
Infere o nome da ferramenta a partir do identificador da função e a descrição a partir da docstring:

```python
# [min-version: 0.3.0]
# [executable]
from chatflow_agent import tool

@tool
def calculate_vat(subtotal: float, rate: float = 0.20) -> float:
    """Calculate Value-Added Tax for an order subtotal."""
    return round(subtotal * rate, 2)

assert calculate_vat.name == "calculate_vat"
assert "Calculate Value-Added Tax" in calculate_vat.description
```

### 2. Decorador Parametrizado
Sobrescreve explicitamente o nome e a descrição expostos ao LLM:

```python
# [min-version: 0.3.0]
# [executable]
from chatflow_agent import tool

@tool(
    name="lookup_stock_ticker",
    description="Fetch the latest real-time market quote for a stock symbol.",
)
def fetch_quote(symbol: str) -> dict:
    """Internal function to retrieve stock prices."""
    # Consulta serviço financeiro
    return {"symbol": symbol.upper(), "price": 182.50, "currency": "USD"}

assert fetch_quote.name == "lookup_stock_ticker"
```

## Mapeamento de Tipos e Introspecção de Esquemas

Quando uma ferramenta é registrada, o `chatflow-agent` inspeciona sua assinatura via módulo padrão `inspect` do Python e constrói um esquema de parâmetros:

| Anotação Python | Tipo Canônico no Esquema | Obrigatório Se |
| :--- | :--- | :--- |
| `str` | `"STRING"` | Nenhum valor padrão atribuído |
| `int` | `"INTEGER"` | Nenhum valor padrão atribuído |
| `float` | `"NUMBER"` | Nenhum valor padrão atribuído |
| `bool` | `"BOOLEAN"` | Nenhum valor padrão atribuído |
| `list` | `"ARRAY"` | Nenhum valor padrão atribuído |
| `dict` | `"OBJECT"` | Nenhum valor padrão atribuído |
| *Não anotado* / `Any` | `"STRING"` (Fallback) | Nenhum valor padrão atribuído |

Parâmetros com valores padrão (ex.: `rate: float = 0.20`) são marcados como opcionais no esquema, enquanto parâmetros sem valores padrão são incluídos no array `required`.

<Callout type="tip" title="Boas Práticas de Docstring">
Modelos de linguagem decidem invocar uma ferramenta com base em seu nome e descrição. Sempre escreva docstrings concisas e sem ambiguidades, detalhando o propósito e os argumentos esperados.
</Callout>

## Execução de Ferramentas Síncronas vs. Assíncronas

O `chatflow-agent` foi projetado com arquitetura assíncrona nativa (*async-first*), mas suporta ferramentas síncronas (`def`) e assíncronas (`async def`) de forma intercambiável.

```python
import asyncio
from chatflow_agent import tool

# Ferramenta síncrona
@tool
def sync_reverse(text: str) -> str:
    """Reverse a string synchronously."""
    return text[::-1]

# Ferramenta assíncrona
@tool
async def async_fetch_status(service_name: str) -> dict:
    """Query service health asynchronously without blocking."""
    await asyncio.sleep(0.01)  # Simula E/S de rede assíncrona
    return {"service": service_name, "status": "healthy"}
```

### Métodos de Execução

* **`await tool.execute_async(**kwargs)` (Recomendado):**
  * Se a ferramenta for `async def`, ela é aguardada diretamente no loop de eventos atual.
  * Se a ferramenta for síncrona `def`, ela é automaticamente despachada para uma thread trabalhadora executora através de `asyncio.to_thread`. Isso garante que cálculos intensivos, operações de E/S em disco ou bibliotecas de rede bloqueantes nunca congelem o loop de eventos principal.
* **`tool.execute(**kwargs)` (Conveniência Síncrona):**
  * Executa ferramentas síncronas diretamente.
  * Se invocada sobre uma ferramenta `async def` fora de um loop de eventos, executa-a utilizando `asyncio.run()`.

<Callout type="warn" title="Proteção do Loop de Eventos">
Invocar <code>tool.execute()</code> sincronicamente em uma ferramenta <code>async def</code> de dentro de um loop de eventos já ativo (por exemplo, dentro de manipuladores FastAPI, Telegram ou turnos do Runner) não é permitido pelo Python e lançará um <code>RuntimeError</code>. Sempre utilize <code>await tool.execute_async()</code> em código assíncrono.
</Callout>

## Diferenças entre Versões e Recursos de Pré-lançamento

A geração de esquemas e execução de ferramentas evoluiu significativamente entre versões:

### Versão Estável (`v0.3.4`)
* <VersionBadge version="0.3.4" status="stable" /> Formato canônico de declaração para Gemini (`to_gemini_declaration()`).
* Mapeamento de tipos de nível único para tipos primitivos e `list`/`dict` não parametrizados.
* Funções síncronas descarregadas via `asyncio.to_thread` durante `execute_async()`.

### Melhorias de Pré-lançamento (`v0.4.0rc1`)
* <VersionBadge version="0.4.0rc1" status="prerelease" /> **Tipagem Profunda de Coleções:** Inspeciona esquemas de itens para `list[T]`, `Sequence[T]`, `set[T]` e tuplas homogêneas `tuple[T, ...]`:

```python
from chatflow_agent import tool

@tool
def sum_metrics(values: list[float]) -> float:
    """Sum a list of numeric measurements."""
    return sum(values)

# Gera: {"type": "ARRAY", "items": {"type": "NUMBER"}}
```

* <VersionBadge version="0.4.0rc1" status="prerelease" /> **Suporte a Union e Optional:**
  * `Optional[T]` ou `T | None` gera `{ "type": "...", "nullable": True }`.
  * `int | float` é ampliado deterministicamente para `"NUMBER"` independentemente da ordem declarada.
  * Uniões de múltiplos tipos geram uma lista de esquemas `anyOf`.
* <VersionBadge version="0.4.0rc1" status="prerelease" /> **`to_openai_parameters()`:** Gera parâmetros no formato JSON Schema (nomes de tipos em minúsculas, `type: "null"` e sem a chave `nullable`) para os motores OpenAI e Anthropic.
* <VersionBadge version="0.4.0rc1" status="prerelease" /> **`ToolSchemaError`:** Valida assinaturas no momento da definição, lançando um `ToolSchemaError` descritivo caso um tipo não suportado não possa ser mapeado para um esquema válido.
* <VersionBadge version="0.4.0rc1" status="prerelease" /> **Exclusão de Varargs:** Argumentos `*args` e `**kwargs` são automaticamente omitidos dos esquemas de parâmetros.

## Isolamento de Erros e Tolerância a Falhas

Em produção, ferramentas podem encontrar timeouts de rede, consultas de banco de dados inválidas ou exceções inesperadas.

O `chatflow-agent` isola falhas de ferramentas dentro do turno de execução. Se uma ferramenta lançar uma exceção não tratada durante a execução:

1. A exceção é interceptada e encapsulada em um `ToolExecutionError`.
2. O `Runner` captura a falha e injeta um `ToolResult` no histórico da conversa marcado com `is_error=True`:
   ```python
   # Injetado no histórico de mensagens para o LLM:
   # ToolResult(tool_call_id="call_123", name="query_db", content="Database connection timeout", is_error=True)
   ```
3. Em vez de interromper toda a conversa do usuário, o agente ativo vê o resultado de erro e pode explicar a questão ao usuário, tentar novamente com parâmetros alternativos ou transferir para uma fila de suporte humano.

## Exemplo Completo: Agente com Múltiplas Ferramentas

```python
from chatflow_agent import Agent, Runner, tool
from chatflow_agent.core.memory import SessionStore

# 1. Definir ferramentas de domínio modulares
@tool
def calculate_shipping(weight_kg: float, destination: str) -> dict:
    """Calculate shipping estimate based on weight and country destination."""
    rate_per_kg = 8.50 if destination.upper() in ["US", "CA"] else 14.00
    total = round(weight_kg * rate_per_kg, 2)
    return {"destination": destination.upper(), "cost_usd": total, "delivery_days": 3}

@tool
def check_inventory(sku: str) -> dict:
    """Check stock availability for a product SKU."""
    return {"sku": sku, "in_stock": True, "warehouse": "east-region-1"}

# 2. Vincular ferramentas ao agente
logistics_agent = Agent(
    name="LogisticsCoordinator",
    instructions="Help customers check inventory availability and calculate shipping rates.",
    tools=[calculate_shipping, check_inventory],
    model="gemini-2.5-flash",
)

# 3. Criar runner com armazenamento de sessão
store = SessionStore()
runner = Runner(starting_agent=logistics_agent, session_store=store)

# 4. Executar turno
response = runner.run(
    session_id="customer-turn-42",
    user_message="Can you check stock for SKU-990 and estimate shipping 2.5 kg to CA?",
)
print("Agent Response:", response.content)
print("Tools Executed:", response.tool_calls_executed)
```

## Armadilhas Comuns e Anti-Padrões

### 1. Esquecer Anotações de Tipo
Parâmetros sem anotação de tipo recorrem por padrão a `"STRING"`. Se sua ferramenta espera números ou booleanos, sempre declare dicas de tipo (*type hints*):
```python
# [INCORRECT]: "count" will be exposed as STRING, requiring manual int casting
@tool
def repeat_phrase(phrase, count): ...

# [CORRECT]: Fully typed parameters produce exact OpenAPI validation
@tool
def repeat_phrase(phrase: str, count: int) -> str:
    return phrase * count
```

### 2. Chamadas de Rede Bloqueantes em Ferramentas Síncronas
Embora ferramentas síncronas sejam despachadas para threads trabalhadoras via `asyncio.to_thread`, operações de rede bloqueantes pesadas sem timeouts podem esgotar o pool de threads do Python. Sempre que possível, implemente ferramentas de E/S de rede usando `async def` com timeouts explícitos.

### 3. Modificar Estado Global em Funções de Ferramentas
As ferramentas devem ser funções puras ou interagir com armazenamento externo através de clientes thread-safe. Evite alterar variáveis globais, pois múltiplas sessões de usuários podem invocar a mesma ferramenta simultaneamente.
