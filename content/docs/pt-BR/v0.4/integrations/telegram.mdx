O `TelegramChannel` conecta enxames do `chatflow-agent` a bots do Telegram. Baseado na biblioteca assíncrona `python-telegram-bot`, ele gerencia polling, isolamento de sessão por chat ID, divisão automática de mensagens em blocos (*chunking*) e políticas de segurança para chats em grupo.

## Instalação

Instale o `chatflow-agent` com o extra `telegram` para incluir as dependências necessárias (`python-telegram-bot>=21.0`):

```bash
pip install "chatflow-agent[telegram]"
```

## Configuração Rápida do Bot

<Steps>
  <Step>
    ### Criar um Bot através do BotFather

    1. Abra o Telegram e procure por [@BotFather](https://t.me/BotFather).
    2. Envie `/newbot` e siga as instruções para escolher um nome de exibição e nome de usuário.
    3. Copie o Token de API HTTP gerado para o bot.
  </Step>

  <Step>
    ### Implementar o Script do Canal

    Crie um script vinculando um `Runner` ao `TelegramChannel`:

```python
import os
from chatflow_agent import Agent, Runner
from chatflow_agent.channels import TelegramChannel
from chatflow_agent.core.memory import SQLiteSessionStore

# Definir seu agente
support_agent = Agent(
    name="SupportBot",
    instructions="You are a helpful customer support representative.",
)

# Configurar armazenamento persistente de sessão
store = SQLiteSessionStore("telegram_sessions.db")
runner = Runner(starting_agent=support_agent, session_store=store)

# Inicializar o Canal do Telegram
telegram = TelegramChannel(
    token=os.environ.get("TELEGRAM_BOT_TOKEN", "your-bot-token"),
    start_message="Welcome! How can I assist you today?",
)

# Vincular runner e executar loop de polling
telegram.attach(runner)

if __name__ == "__main__":
    print("Starting Telegram bot polling...")
    telegram.run()
```
  </Step>
</Steps>

## Parâmetros de Configuração do Canal

O construtor do `TelegramChannel` aceita as seguintes opções:

| Parâmetro | Tipo | Padrão | Descrição |
| :--- | :--- | :--- | :--- |
| `token` | `str` | *Obrigatório* | Token de API do bot do Telegram emitido pelo @BotFather. |
| `start_message` | `str` | `"Hello! I am your AI..."` | Mensagem de saudação enviada quando um usuário aciona `/start`. |
| `fallback_message` | `str` | `"Disculpa, ocurrió un..."` | Mensagem amigável enviada ao usuário quando a execução do modelo falha. |
| `allowed_updates` | `list[str] \| None` | `None` | Restringe tipos de atualizações (ex.: `["message"]`). O padrão é todas. |

## Comandos Embutidos e Segurança em Chats de Grupo

O `TelegramChannel` inclui manipuladores de comando pré-configurados:

### Comando `/start`
Responde com a `start_message` para apresentar o assistente aos novos usuários.

### Comando `/reset`
Limpa o histórico da sessão no `runner.session_store` para o chat ID ativo, permitindo que os usuários recomecem a conversa do zero.

<Callout type="warn" title="Segurança em Grupos e Supergrupos">
Em chats de grupo e supergrupos, permitir que qualquer participante limpe o histórico poderia prejudicar outros usuários. O `TelegramChannel` impõe verificação de funções:
* **Criadores e Administradores:** Autorizados a executar `/reset`.
* **Membros Padrão:** Execução bloqueada com a resposta: `"Only group admins can reset the conversation."`.

## Divisão de Mensagens de Saída (`split_message`)

O Telegram impõe um limite estrito de **4096 caracteres por mensagem de texto**. Quando um agente gera análises longas, blocos de código ou tabelas, o envio direto do texto completo faz a API do Telegram retornar HTTP 400.

O `TelegramChannel` processa automaticamente as respostas através de `split_message`:

```python
# [min-version: 0.3.2]
# [executable]
from chatflow_agent.channels import split_message

long_text = "Detailed agent analysis..." * 200
chunks = split_message(long_text, max_len=4096)
# Divide progressivamente em \n\n, \n, . ou espaços para preservar a legibilidade
```

O canal entrega os blocos sequencialmente. `split_message` prefere limites de parágrafo, linha, frase e, por fim, de palavra; quando um bloco não contém nenhum separador (por exemplo, uma URL muito longa), recorre a um corte rígido em `max_len`. Os comprimentos são contados em caracteres Python, e `max_len` deve ser positivo.

## Indicadores de Digitação e Experiência do Usuário

Quando uma mensagem chega, o `TelegramChannel` envia um único indicador `ChatAction.TYPING` antes de despachar o turno (erros dessa chamada são ignorados). Ele não é repetido enquanto o turno é executado, portanto, em turnos longos, o status de digitação do Telegram pode desaparecer antes de a resposta chegar.

## Gerenciamento do Loop de Eventos

`run()` inicia o long polling e bloqueia: ele mesmo conduz o loop de eventos através do `run_polling()` do python-telegram-bot. Na v0.4.0rc1, ele também abre o escopo `async with runner:` do runner anexado durante todo o tempo de vida da aplicação (aberto em `post_init`, fechado em `post_shutdown`), de modo que os turnos reutilizam conexões Gemini em pool. Passar `close_loop=False` mantém o loop de eventos aberto depois que `run()` retorna:

```python
telegram.run(drop_pending_updates=True, close_loop=False)
```

`close_loop=False` não torna `run()` utilizável dentro de um loop de eventos que já está em execução, como o de uma aplicação FastAPI. O `TelegramChannel` não fornece um método de inicialização não bloqueante.
