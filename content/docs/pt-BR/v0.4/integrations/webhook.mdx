Embora o `chatflow-agent` forneça canais pré-construídos para Telegram e WhatsApp, sistemas modernos frequentemente demandam conectar enxames multiagente a microsserviços internos, APIs de eventos do Slack, bots do Discord ou webhooks de CRM (Zendesk, Intercom).

O `chatflow-agent` não inclui um canal de webhook genérico. O extra opcional `webhook` apenas instala `fastapi>=0.110.0` e `uvicorn>=0.29.0`; você mesmo escreve o endpoint, seja como uma subclasse de `BaseChannel` (como abaixo) ou chamando `runner.run_async()` a partir de uma rota existente. O repositório do SDK inclui uma aplicação de referência completa em [`examples/webhook_api_service.py`](https://github.com/GustavoBaranda/chatflow-agent/blob/v0.4.0rc1/examples/webhook_api_service.py).

## A Arquitetura do BaseChannel

Todos os canais de comunicação herdam de `BaseChannel`. Ele estabelece um ciclo de vida padronizado:

```
[ Incoming HTTP Webhook ]
           |
           v
+-------------------------------------------------------------------+
|            Your custom channel (BaseChannel subclass)             |
|   1. Authenticate Request (API Key or HMAC Signature)             |
|   2. Extract session_id, message, and metadata                    |
|   3. Forward via dispatch_async(session_id, message, metadata)    |
+---------------------------------+---------------------------------+
                                  |
                                  v
+---------------------------------+---------------------------------+
|                       chatflow-agent Runner                       |
|   - Session Lock (serializes turns of a session) & Memory Refresh |
|   - Multi-Agent Orchestration & Tool Calling                      |
|   - State Persistence                                             |
+---------------------------------+---------------------------------+
                                  |
               AgentResponse (content, active_agent_name)
                                  |
                                  v
[ Immediate HTTP Response or Async Webhook Callback ]
```

### Métodos Fundamentais do BaseChannel

```python
from chatflow_agent.channels import BaseChannel

class MyChannel(BaseChannel):
    """Minimal channel definition."""

    def run(self, **kwargs):
        """Start the listening service."""
        pass
```

* `attach(runner: Runner) -> BaseChannel`: Vincula uma instância do Runner multiagente ao canal.
* `dispatch_async(session_id: str, message: str, metadata: dict | None = None) -> AgentResponse`: Encaminha a mensagem ao runner vinculado de forma assíncrona (`runner.run_async`). Na v0.4.0rc1, os turnos de uma mesma sessão são serializados tanto para `SessionStore` quanto para `SQLiteSessionStore` (por store e por event loop).
* `dispatch(session_id: str, message: str, metadata: dict | None = None) -> AgentResponse`: Contraparte síncrona para ambientes de execução síncronos.

`split_message(text: str, max_len: int = 4096) -> list[str]` não é um método de `BaseChannel`, e sim um utilitário em nível de módulo para dividir respostas longas: `from chatflow_agent.channels import split_message`.

## Implementando uma Base Segura de Webhook com FastAPI

O canal customizado a seguir oferece uma base segura de HMAC e roteamento de sessões. Implantações em produção devem aplicar, adicionalmente, proteção contra replay específica do provedor, rotação de segredos, limitação de taxa, limites de tamanho de requisição e monitoramento operacional.

```python
import hmac
import hashlib
from typing import Any
from fastapi import FastAPI, Header, HTTPException, Request
import uvicorn
from chatflow_agent import Agent, Runner
from chatflow_agent.channels.base import BaseChannel, ChannelError

class GenericWebhookChannel(BaseChannel):
    """Custom webhook receiver supporting HMAC verification and session routing."""

    def __init__(self, secret: str) -> None:
        super().__init__()
        if not secret:
            raise ValueError("A non-empty webhook signing secret is required")
        self.secret = secret
        self.app = FastAPI(title="Agent Webhook Channel")
        self._setup_routes()

    def _setup_routes(self) -> None:
        @self.app.post("/api/v1/chat")
        async def handle_chat_webhook(
            request: Request,
            x_signature: str | None = Header(default=None, alias="X-Webhook-Signature"),
        ) -> dict[str, Any]:
            body_bytes = await request.body()

            if not x_signature:
                raise HTTPException(status_code=403, detail="Missing signature")

            expected = hmac.new(
                self.secret.encode("utf-8"), body_bytes, hashlib.sha256
            ).hexdigest()
            if not hmac.compare_digest(expected, x_signature):
                raise HTTPException(status_code=403, detail="Invalid signature")

            data = await request.json()
            authenticated_user_id = data.get("user_id")
            message = data.get("message", "")

            if not authenticated_user_id or not message:
                raise HTTPException(status_code=400, detail="Fields 'user_id' and 'message' are required")

            # O corpo assinado autentica esta identidade. Nunca use uma sessão compartilhada.
            session_id = f"webhook:{authenticated_user_id}"
            metadata = {"authenticated_user_id": authenticated_user_id}

            # Despachar diretamente no runner vinculado
            try:
                response = await self.dispatch_async(session_id, message, metadata=metadata)
                return {
                    "session_id": session_id,
                    "reply": response.content,
                    "agent": response.active_agent_name,
                }
            except ChannelError as err:
                raise HTTPException(status_code=500, detail="Channel dispatch failed") from err

    def run(self, host: str = "0.0.0.0", port: int = 8080) -> None:
        """Start Uvicorn server."""
        self._ensure_runner_attached()
        uvicorn.run(self.app, host=host, port=port)
```

## Executando o Serviço de Webhook

Conecte o canal ao seu agente e runner:

```python
import os
from chatflow_agent import Agent, Runner
from chatflow_agent.core.memory import SQLiteSessionStore

# 1. Definir o agente
assistant = Agent(
    name="APIAssistant",
    instructions="You are an automated API assistant.",
)

# 2. Configurar armazenamento persistente
store = SQLiteSessionStore("webhook_sessions.db")
runner = Runner(starting_agent=assistant, session_store=store)

# 3. Instanciar o canal e vincular o runner
# Ler o segredo de assinatura do ambiente; nunca o coloque fixo no código
channel = GenericWebhookChannel(secret=os.environ["WEBHOOK_SIGNING_SECRET"])
channel.attach(runner)

if __name__ == "__main__":
    channel.run(host="0.0.0.0", port=8080)
```

## Montando Dentro de Aplicações FastAPI Existentes

Se seu backend já executa uma aplicação FastAPI ou Starlette, não há necessidade de um servidor separado. A rota ainda deve autenticar o remetente antes de derivar seu ID de sessão. A dependência abaixo representa a camada de autenticação já existente na sua aplicação:

```python
from typing import Annotated
from fastapi import FastAPI, Depends
from chatflow_agent import Agent, Runner

app = FastAPI()

agent = Agent(name="RouterAgent", instructions="Triage support requests.")
runner = Runner(starting_agent=agent)

def require_authenticated_sender() -> str:
    """Validate the request credential and return its immutable subject."""
    raise NotImplementedError("Connect this dependency to your authentication system")

@app.post("/crm/webhook")
async def crm_webhook_endpoint(
    payload: dict,
    authenticated_subject: Annotated[str, Depends(require_authenticated_sender)],
):
    session_id = f"crm:{authenticated_subject}:{payload['customer_id']}"
    incoming_text = payload["ticket_description"]

    # Executar o agente diretamente
    response = await runner.run_async(
        session_id=session_id,
        user_message=incoming_text,
        metadata={"priority": payload.get("priority")},
    )

    return {"status": "processed", "solution": response.content}
```

## Melhores Práticas de Segurança

<Callout type="warn" title="Checklist de Segurança para Produção">
* **Validação de Assinatura HMAC:** Sempre verifique assinaturas recebidas (ex.: `X-Hub-Signature-256`, `X-Slack-Signature`) utilizando `hmac.compare_digest` para evitar ataques de temporização (*timing attacks*).
* **Tokens de Autenticação:** Exija um token de API ou cabeçalho Bearer token caso o webhook se origine de microsserviços internos.
* **Confirmação Imediata para Ferramentas Lentas:** Caso seu agente invoque ferramentas de longa duração, retorne um `HTTP 200` imediato ao provedor do webhook e despache o turno do agente como uma tarefa em segundo plano (`asyncio.create_task`), transmitindo o resultado via URL de retorno (*callback*).
</Callout>
