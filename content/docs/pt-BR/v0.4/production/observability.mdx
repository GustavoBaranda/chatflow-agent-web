Operar enxames multiagente em produção requer visibilidade completa. Quando um agente transfere uma conversa, invoca APIs externas ou aciona fallbacks, os operadores precisam de logs estruturados e IDs de correlação para diagnosticar latências, investigar anomalias e auditar decisões.

O `chatflow-agent` v0.4.0rc1 usa loggers da biblioteca padrão do Python para o runner, as ferramentas, os armazenamentos de sessão, os motores de provedores e as integrações de canais. As aplicações podem anexar seu próprio formatador estruturado.

## Hierarquia de Loggers

Todos os loggers estão organizados sob o namespace `chatflow_agent`. Você pode configurar a verbosidade globalmente ou ajustar componentes individuais:

```text
chatflow_agent
├── chatflow_agent.runner      (Tool execution failures with trace_id; failed rollbacks)
├── chatflow_agent.tools       (Tool schema warnings, e.g. unresolved annotations)
├── chatflow_agent.memory      (Session deleted or modified during a turn)
├── chatflow_agent.engine
│   ├── chatflow_agent.engine.openai     (Retry warnings: HTTP status and connect errors)
│   ├── chatflow_agent.engine.gemini     (Retry warnings for REST requests; API key redacted)
│   └── chatflow_agent.engine.anthropic  (Retry warnings: HTTP status and connect errors)
├── chatflow_agent.telegram    (Polling start, /reset permission errors, message errors)
└── chatflow_agent.whatsapp    (Signature rejections, duplicates, timeouts, outbound delivery)
```

O SDK não emite métricas nem traces, e os loggers dos motores não registram cargas úteis de requisições, latência ou contagens de tokens. Adicione essa instrumentação na sua aplicação, se precisar dela.

## Configurando Logging Estruturado

Em ambientes de produção, formate os logs como registros JSON em linha única para que sistemas de ingestão centralizados (como Datadog, CloudWatch ou Google Cloud Logging) possam indexar os campos automaticamente:

```python
import json
import logging
import sys
from chatflow_agent import Agent, Runner

class JSONLogFormatter(logging.Formatter):
    """Format log records as structured JSON."""
    def format(self, record: logging.LogRecord) -> str:
        log_entry = {
            "timestamp": self.formatTime(record, self.datefmt),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
            "module": record.module,
            "lineno": record.lineno,
        }
        if record.exc_info:
            log_entry["exception"] = self.formatException(record.exc_info)
        return json.dumps(log_entry)

def setup_production_logging(log_level: int = logging.INFO) -> None:
    """Initialize structured JSON logging for chatflow-agent."""
    handler = logging.StreamHandler(sys.stdout)
    handler.setFormatter(JSONLogFormatter())
    
    # Configure root logger
    root_logger = logging.getLogger("chatflow_agent")
    root_logger.setLevel(log_level)
    root_logger.handlers = [handler]
    root_logger.propagate = False

if __name__ == "__main__":
    setup_production_logging()
    
    agent = Agent(name="ObservabilityBot", instructions="Test logging.")
    runner = Runner(starting_agent=agent)
    print("Structured logging configured.")
```

## Correlação de Rastreamento com `trace_id`

Quando uma ferramenta falha durante a execução, o `Runner` gera automaticamente um UUID `trace_id` aleatório e o anexa tanto ao registro de log interno quanto à mensagem entregue ao agente:

```text
[ERROR] 2026-10-30T18:22:15Z chatflow_agent.runner: Tool execution failed [trace_id: 3c9b7e41-0f2d-4e92-bc12-f71e549d8802] - Tool: 'query_database' on agent 'BillingAgent': Error executing tool 'query_database': Connection timed out to db.internal.corp:5432
```

O registro é emitido com `exc_info=True`, portanto seu handler também recebe o stack trace.

### Por Que a Correlação é Fundamental

1. **Privacidade do Usuário:** O modelo e, portanto, o usuário final recebem apenas a mensagem genérica com o `trace_id`, não o texto da exceção nem endereços internos.
2. **Triagem Determinística:** Quando um usuário relata *"Minha consulta falhou às 18:22"*, engenheiros de suporte podem pesquisar diretamente por `trace_id: 3c9b7e41...` nos logs para inspecionar a exceção e seu stack trace. Os argumentos da ferramenta não são registrados no log.

## Inspecionando a Telemetria da Resposta

Toda invocação de `Runner.run()` ou `Runner.run_async()` retorna um objeto `AgentResponse` contendo metadados de execução:

```python
from chatflow_agent import Agent, Runner

agent = Agent(name="Inspector", instructions="Provide analytical responses.")
runner = Runner(starting_agent=agent)

response = runner.run(
    session_id="session-user-99",
    user_message="Calculate quarterly forecast.",
)

# 1. Texto entregue ao usuário
print(f"Content: {response.content}")

# 2. Agente ativo final que formulou a resposta
print(f"Active Agent: {response.active_agent_name}")

# 3. Lista dos nomes das ferramentas executadas durante o turno
print(f"Tools Executed: {response.tool_calls_executed}")

# 4. Detalhes da transferência caso tenha ocorrido um handoff
if response.handoff:
    print(f"Transferred to: {response.handoff.target_agent_name}")
    print(f"Reason: {response.handoff.reason}")
```

## Auditoria e Inspeção do Histórico da Conversa

Para inspecionar os turnos conversacionais armazenados em uma sessão, recupere o contexto de sessão diretamente do armazenamento configurado:

```python
from chatflow_agent import Agent, Runner
from chatflow_agent.core.memory import SessionStore

store = SessionStore()
agent = Agent(name="Support", instructions="Help customers.")
runner = Runner(starting_agent=agent, session_store=store)

# Executar o turno
runner.run(session_id="sess-42", user_message="Hello, I need assistance.")

# Inspecionar a sessão armazenada
session = store.get(session_id="sess-42")
if session:
    print(f"Total Messages: {len(session.history)}")
    for msg in session.history:
        print(f"[{msg.role.value}] {msg.content}")
```

<Callout type="warn" title="Dados Sensíveis nos Logs">
O <code>chatflow-agent</code> não instala nenhum filtro de log. Seus motores não registram cabeçalhos de requisição, o <code>GeminiEngine</code> remove sua chave de API das mensagens de erro e dos logs, e o <code>WhatsAppChannel</code> mascara números de telefone em suas próprias mensagens. Outros conteúdos ainda podem chegar aos seus logs: mensagens de exceção de ferramentas, corpos de erro de provedores incluídos em <code>ProviderError</code> (com tamanho limitado) e respostas de erro da Meta. O logging por si só não torna uma implantação conforme com SOC 2, LGPD/GDPR ou frameworks semelhantes; adicione filtros de redação e políticas de retenção adequados aos seus requisitos.
